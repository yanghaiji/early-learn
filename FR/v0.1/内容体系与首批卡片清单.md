**分类设计原则**

1. 覆盖 1–3 岁日常高频认知对象，逐步向上兼容 4–10 岁（英语主题词与汉字分层）；不追求学术完整性，只求「孩子看得见、摸得着」。
2. 首页用自适应网格承载 16 个分类入口（手机 2–3 列、平板 4 列、桌面 5 列），不引入二级分类。v0.1.7 起分类内可再按**主题组**筛选（汉字 7 组、古诗 2 组），组归属于 `characterGroups.ts` 维护，不是可管理的二级分类，也不新增路由层级。
3. 颜色 / 形状 / 数字三类**不使用照片**，使用统一风格的纯色或几何图形（见 4.2 例外规则）；v0.1.3 新增的 5 个主题分类沿用同一 emoji 字形管线。
4. 汉字卡与实物卡可能存在同名字（如「手」「牛」），通过 `id` 前缀与 `kind` 区分，允许共存。主题分类与旧分类也存在同义卡（如 `family-dad` 与「爸」字），这是刻意设计：实物卡学词，汉字卡学形。

| 项 | 规则 | 示例 |

| 清单 | `assets/images/manifest.json`（尺寸/字节/生成时间） | — |

## 3. 字段填写标准

### 3.1 拼音规则

- 一律**小写 + 声调符号**，不使用数字声调（`píng guǒ` ✅ / `ping2 guo3` ❌）。
- 音节之间用**半角空格**分隔；轻声不标调（`hóu zi`）。
- 词语连写不粘连、不换行：`xióng māo`、`zì xíng chē`。
- ü 写作 `ü`（`lǜ sè`）。

### 3.2 英文规则

- 单词或常用词组，≤ 3 个单词，首字母小写（专名除外）。
- 用最常见、最贴近幼儿认知的词：`car` 优于 `automobile`，`tummy` 可作 `belly` 的同义补充放 `tags`。
- 不写复数、不加冠词。

### 3.3 音标（可选）

- IPA 格式，含首尾 `/`，如 `/ˈæpl/`、`/kæt/`。
- 若不确定，**留空**而非猜测；音标错误会直接误导发音学习。

### 3.4 难度（`difficulty`）

| 值 | 含义 | 适用 |
| --- | --- | --- |
| 1 | 最常见、单音节、实物大而清晰 | 猫、狗、苹果、手 |
| 2 | 双音节或稍抽象 | 草莓、公交车、鼻子 |
| 3 | 多音节、概念词 | 救护车、长方形、消防车 |

### 3.5 标签（`tags`）

用于 v0.2 的筛选与拓展（如「农场」「会叫的」「红色系」）。v0.1 仅存储，不做 UI 筛选。每个卡片 ≤ 5 个。

## 4. 图片素材规范（内置插画 + 可选实拍）

### 4.0 v0.1 内置素材（已落地）

- 生成方式：`npm run prepare:images`（解析 `src/data/seed/cards.ts` → SVG → sharp → WebP 质量 82）。
- 风格：分类主题色底 + 白色圆角主体；动物/水果/蔬菜/交通/日常/身体用 emoji 字形，颜色用色块、形状用几何形、数字用字号字形、汉字用楷体字形。
- 诗词（v0.1.5）：宣纸底 `#F7F4EC` + 淡墨远山 + 一点赭石/水青，按 20 个意境场景（月夜/山/峡谷/江/湖/柳/水禽/田/花/瀑/雪/楼/亭/茅屋/林/秋/荷/春/秋千）套用。
- 体量：451 张卡片（320×320）+ 16 张封面（480×360），共 467 个 WebP，单张最大 5.6KB，合计约 1.35MB。
- 可维护性：`--force` 全量重生成，`--only=animals` 只生成单个分类；换真图时保留同路径覆盖即可，seed 与代码零改动。

### 4.1 来源与授权（自行替换时适用）

| 优先级 | 来源 | 授权 | 注意 |
| --- | --- | --- | --- |
| 1 | 自摄 | 自有版权 | 最优：背景可控、无版权风险 |
| 2 | Pexels / Pixabay / Unsplash | 免费商用（各自许可） | 需逐张登记 `source`；避免抓取带品牌 logo 的图 |
| 3 | Openverse（CC0 / CC BY） | 按图单独确认 | CC BY 必须保留署名（写入 `source.author`） |
| 4 | Wikimedia Commons | 多为 CC BY-SA | 需遵守相同方式共享，谨慎使用 |

**禁止**：百度/小红书/电商详情页等来源不明图片、带水印图、含明显真人面部特写（身体部位类需裁切到局部）、含可读品牌文字的包装图。

每张图必须登记：

```json
"source": { "provider": "pexels", "author": "Jane Doe", "url": "https://...", "license": "Pexels License" }
```

### 4.2 视觉标准

| 项 | 要求 | 例外 |
| --- | --- | --- |
| 比例 | 1:1 正方形 | — |
| 背景 | 纯白或接近白（`#FFFFFF` ~ `#F7F7F7`），无杂物 | 身体部位可用浅肤色背景 |
| 主体占比 | 55%–80%，居中，四边留白均匀 | 交通工具可 70%–85% |
| 光线 | 均匀柔光，无强阴影/反光 | — |
| 色彩 | 自然色，不使用滤镜与强对比 | 颜色类必须为纯色块 |
| 分辨率 | 原图 ≥ 1024×1024，卡片图输出 320×320（居中裁切） | — |
| 体积 | 卡片图 ≤ 30KB，封面 ≤ 40KB（WebP，质量 78–82） | — |
| 文字 | 图中不得出现可读文字 | 数字类可含数字字形 |

**例外（非照片类）**

| 分类 | 做法 |
| --- | --- |
| `colors` | 纯色色块（`#E5484D` 等 8 色），可加极浅描边区分白色 |
| `shapes` | 单色几何形（主色 + 中性描边），形状居中 |
| `numbers` | 大号数字字形（统一字体），可配对应数量的小圆点 |
| `characters` | 汉字字形图（可选）或纯文字渲染，墨色 `#2B2B2B` |

### 4.3 素材处理流程

```
1. 内置素材：运行 npm run prepare:images 直接生成（无需联网）
2. 替换实拍：原图暂存 .tmp/images-raw/（规约：临时文件必须落在项目内）
3. 裁剪为 1:1  → 主体居中 → 导出 320×320 WebP 覆盖同名文件
4. 如为第三方图，填写 source 与 license → 写入 seed 卡片
5. 目检：在 320px 下仍可辨识（幼儿在平板上看到的就是这个尺寸）
6. 跑 npm run validate:content 校验图片齐备 → 清理 .tmp/images-raw/
```

### 4.4 图片验收清单

- [x] 1:1、背景干净、主体居中、无文字水印
- [x] 320px 下 1 秒内可认出是什么
- [x] 内置素材为项目原创（脚本生成），无需逐张登记 license
- [x] 卡片图 ≤ 30KB、封面 ≤ 40KB
- [x] 与同分类其他图风格一致（同一脚本同一主题色体系）
