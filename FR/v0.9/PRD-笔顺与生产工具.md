## 1. 背景与诉求

v0.8.0（分龄与拼音辅助）交付后，需求方要求「继续大版本规划」。立项前核对了两组现状，各自都卡在一个具体缺口上。

### 1.1 孩子侧：笔顺只有数字，没有「怎么写」

| 核查项 | 现状 | 问题 |
| --- | --- | --- |
| 汉字卡数据 | 321 张 `kind=character`，只有 `strokes: number`（如「人 2 画」）与 `words` | 详情页把「2 画」当**结果**告诉家长，却看不到**过程**；1–3 岁的孩子最需要的恰恰是「一笔一笔怎么落笔」 |
| 笔顺数据 | 全库没有任何笔顺路径，种子图片是美术字（`assets/images/characters/*.webp`），不是可分解的字形 | 逐笔演示必须引入外部笔顺字形数据（Make Me a Hanzi 系），且 321 字若全量内联会把首屏拖垮 |
| v0.8.0 遗留 | PRD §4 第 1 条明确「不做笔顺动画」，数据口径已定（321 字全覆盖 + 按 8 个主题组切片懒加载） | 口径定了但没落地，是这一版必须补的第一件事 |

### 1.2 家长侧：能看能管，但录不动、存不下、改坏了回不去

| 核查项 | 现状 | 问题 |
| --- | --- | --- |
| 批量录入 | 只有「导入 JSON（合并 / 替换）」，`bulkUpsert` 在仓储层已就绪但**没有 UI** | 家长用 Excel 整理好 50 张卡，必须先手搓成「童识」导出的完整 JSON 才能进库；分类可以被导入包带着一起改，只想「加几张卡」时风险过大 |
| 上传图片 | `readImageAsDataUrl` 只做 `≤ 500 KB` 校验，**不压缩**，原图直接转 base64 存进 localStorage | base64 膨胀约 4/3 → 单张 500 KB 的图占 667 KB；localStorage 约 5 MB，**实际只放得下 7 张左右**，再存就整库写不进去（`StorageQuotaError`） |
| 回滚 | 只有一份 `early-learn:v1:auto-backup`，且**没有任何入口能读它**；「恢复内置内容」是单向的 | 误删分类、导入错包（合并模式覆盖同 id 卡）之后没有「退回上一步」的路，只能靠用户自己事先导出 |
| 存储位置 | 内容文档单 key 存在 localStorage，`usageBytes()` 已能统计占用 | 快照若同放 localStorage 会与主文档抢 5 MB 配额，越用越紧 |

本版把这两组缺口合成一个版本：笔顺是「孩子看得见」的可见价值，生产工具是「家长录得动」的持续能力，二者互不依赖、可分段验收。

## 2. 需求条目

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| US-X1 | 笔顺动画 | 汉字卡详情页：大字下方新增「看笔顺」按钮，点击在**原大字位置**用 SVG 逐笔演示；演示中可停止，结束后可重播；不自动播放 |
| US-X2 | 笔顺数据与切片 | 321 张汉字卡全覆盖；数据按现有汉字 8 个主题组切片，**点开某个字才载入它所在那组**；不在数据里的字不显示按钮、不报错 |
| US-X3 | 动画可关 | 遵循设置页已有的「减少动画」（`reduceMotion`）：开启时点「看笔顺」直接显示整字，不做逐笔推进，并说明原因 |
| US-X4 | CSV 批量录入 | 数据管理 → 导入区新增「选择 CSV 文件」：一次录入多张卡（只加卡片、不动分类），预览里给出「新增 / 重复 / 错误」明细；**任何一行不合法则整表不写入**；提供 CSV 模板下载 |
| US-X5 | 上传图压缩 | 卡片表单选图后自动压缩：最长边 1280、优先 WebP、目标 ≤ 150 KB；压缩过程与结果（原体积 → 压缩后体积）对家长可见；原图上限由 500 KB 放宽到 8 MB |
| US-X6 | 内容快照 | 数据管理 → 维护区新增「内容快照」：可手动「立即备份」，批量导入 / 替换导入 / 恢复内置内容 / 恢复快照前**自动建一份**；保留最近 5 份，超出淘汰最旧 |
| US-X7 | 一键回滚 | 快照列表显示「时间 · 来源 · 张数 · 体积」；点「恢复」二次确认后，先为当前状态建一份「恢复前」快照，再用该快照覆盖内容，并提示恢复结果 |
| US-X8 | 快照降级 | 浏览器不支持或禁用 IndexedDB（隐私模式等）时，快照面板显示「本机不支持快照」并保留导出 JSON 的备份路径，不阻塞其它功能 |
| US-X9 | 不做破坏性变更 | 不新增路由、不改 `Card` / `Category` 字段、不改 `schemaVersion` / `SEED_VERSION`、不改导入导出 JSON 结构与既有交互；笔顺数据与 hanzi-writer 均为**懒加载**，首屏 chunk 不增长 |

## 3. 验收标准

> 「实测」列在实现后回填；本版动手前先按此表写测试与 CDP 脚本。

| 项 | 标准 | 实测 |
| --- | --- | --- |
| 笔顺覆盖 | 321 张汉字卡全部能播；数据内每字 `strokes.length` 与卡片 `strokes` 字段**一一相等** | 已实测：321 / 缺字 0；`strokes.test.ts` 逐张比对相等（并纠正 6 处卡片笔画数） |
| 笔顺交互 | 点「看笔顺」开始逐笔演示；演示中按钮变「停止」；结束后按钮变「重播」；不点不播 | 已实测（360 / 1440）：`看笔顺 → 停止 → 重播` 三态正确，停止后保留已画笔画，重播 2 ms 响应 |
| 笔顺降级 | `reduceMotion` 开启时不做逐笔推进，直接显示整字，并有一句说明；数据缺字时无按钮、无报错 | 已实测：开启后按钮即「显示整字」+ 说明句，点击 94 ms 出整字；断网首开 toast 提示并回落静态大字，无白屏、无异常 |
| 笔顺体积 | 主 chunk 不增长；「看笔顺」链路（渲染器 + 库）与 8 个数据块各自懒加载，单块 gzip ≤ 60 kB | 已实测：主 chunk gzip 197.08 → **197.56**（+0.48，预算内）；`StrokePlayer` **12.13**；8 块 13.93–**60.34**（daily 超限 0.34 kB，已记 NFR §7.1）；打开详情只拉 `StrokePlayer`，点击才拉组数据 |
| 门禁 | typecheck / lint / test / build / validate:content 全绿，且 `validate:content` 新增笔顺数据一致性校验 | 前五道全绿（325 例全绿）；V8 一致性校验归 T-X12，尚未接 |
| CSV 正常路径 | 10 行合法 CSV 一次录入 10 张，分类分布与预览一致；同一分类内排序接在现有卡片之后 | 待实测 |
| CSV 整表拒绝 | 任意一行缺必填 / 拼音无声调 / 分类名不存在时，整表不写入，预览逐条列出「第 n 行 · 字段 · 原因」，最多展示 10 条并给总数 | 待实测 |
| CSV 重复处理 | 同分类内与现有卡片同名（`zh` 相同）的行标为「重复」，默认跳过并在预览中单列，不阻断其余行 | 待实测 |
| 图片压缩 | 选一张 3 MB 照片，提示压缩结果且写入的 dataURL 解码后 ≤ 150 KB；导出 JSON 体积相应下降 | 待实测 |
| 图片兼容 | 浏览器不支持 WebP 编码时回退 JPEG，仍满足 ≤ 150 KB；压缩失败给出原因且不写入卡片 | 待实测 |
| 快照生命周期 | 手动备份 + 4 次自动备份后列表为 5 条，第 6 次淘汰最旧一条；恢复后内容与快照一致（张数、分类、字段） | 待实测 |
| 恢复安全性 | 恢复前自动生成「恢复前」快照；恢复只覆盖内容，不触碰学习进度（收藏 / 标记 / 最近浏览） | 待实测 |
| 零回归 | 分龄 / 搜索 / 收藏 / 复习 / 听音选图 / 连播 / 导入导出与 v0.8.0 行为一致 | 待实测 |
| 门禁 | typecheck / lint / test / build / validate:content 全绿，且 `validate:content` 新增笔顺数据一致性校验 | 前五道全绿（325 例全绿）；V8 一致性校验归 T-X12，尚未接 |

## 4. 本版不做

1. **不做笔顺练习（描红 / 判断笔顺对错）**：`hanzi-writer` 自带 quiz 能力，但写错判罚、计分与幼儿挫败感需要单独设计，留待后续版本。
2. **不做笔顺发音（读笔画名：横 / 竖 / 撇）**：需要另一套笔画名音频与朗读时序，与「点读」是两件事。
3. **不改种子图片**：汉字卡的美术字图（`characters/*.webp`）不动，笔顺是叠加在详情页大字上的演示层。
4. **不做分类封面图片上传与压缩**：现在分类封面只走预设，本版只压缩卡片表单的图片。
5. **不做 CSV 导出**：导出仍以 JSON 全量为准，CSV 只是「录入」通道，避免两套备份格式打架。
6. **不做 CSV 覆盖更新**：CSV 只新增；要改已有卡走单卡表单或 JSON 合并，避免「同名列一空就把旧值清掉」。
7. **不做快照的云同步 / 分享**：快照只在本机 IndexedDB，导出迁移仍走 JSON。
8. **不引入后端**：v1.0「云端协同」的事，本版不做。

## 5. 口径

### 5.1 已确认（2026-10-31 需求方选定）

| 编号 | 口径 | 取值 | 理由 |
| --- | --- | --- | --- |
| D-X1 | 笔顺渲染方式 | 引入 `hanzi-writer`（MIT，零运行时依赖）而非自写 SVG 渲染器 | 现成的逐笔时序、描边动画、暂停/重播与轮廓显示，自写约 200 行但细节（笔序、连笔、缩放）要反复调；代价是新增一个懒加载依赖，可控 |
| D-X2 | 笔顺数据切片 | 按汉字 8 个主题组切成 8 个动态 import 模块 | 与 v0.8 拼音字典同思路：构建期出静态模块、运行时按需载入；单块约 40 字、预估 gzip 25–60 kB，首屏与分类页零增长 |
| D-X3 | CSV 非法行 | **整表拒绝** | 与现有 JSON 导入的「一张不合法整体拒绝」保持一致，不引入「部分成功」的回退口径 |
| D-X4 | 快照存储与份数 | IndexedDB，保留最近 5 份 | localStorage 只有约 5 MB，快照与主文档抢配额；IndexedDB 容量宽松，且 5 份能覆盖「改错 → 发现 → 回退」的真实时间窗 |
