# 分类归属纠偏 · 产品需求（v0.11.0）

> 起因：v0.10 首页按语义把 22 个分类切成「认物 / 字卡 / 诗文 / 绘本」四段后，需求方仍然说「分类不明确」。
> 逐张核对 809 张卡后确认：**问题不在排版，在归类本身**——同一件东西挂在两个分类里，或挂在了更宽的那个分类里。

---

## 1. 问题（逐张核对后的实测事实）

| 卡片 | 现在挂在 | 应该挂在 | 证据 |
| --- | --- | --- | --- |
| 蜜蜂 `bee` | 动物 22 | 小虫子 10 | 小虫子已有瓢虫 / 蜘蛛 / 蜻蜓 / 蚱蜢 / 蝉 / 蚂蚁 |
| 蝴蝶 `butterfly` | 动物 22 | 小虫子 10 | 同上；蝴蝶与蜜蜂属昆虫纲 |
| 鱼 `fish` | 动物 22 | 海洋动物 10 | 海洋动物已有鲸鱼 / 海豚 / 鲨鱼 / 章鱼 / 海马 |
| 鞋子 `shoes` | 日常用品 15 | 穿戴 10 | 穿戴已有靴子 / 袜子 / 手套 / 围巾，缺的正是最基础的鞋与帽 |
| 帽子 `hat` | 日常用品 15 | 穿戴 10 | 同上 |
| 书包 `backpack` | 日常用品 15 | 学校用品 12 | 学校已有铅笔 / 尺子 / 本子 / 教室，书包是上学这件事的核心物件 |
| 老师 `teacher` | 家人 12 | 职业 10 | 职业已有医生 / 护士 / 警察 / 厨师；老师不是家庭成员 |

两条结构性事实（v0.10 PRD §1 已记，本版再次确认）：

- **认物 17 个入口只对应 210 张（26%），字卡 2 个入口对应 349 张（43%）**：入口数与内容量倒挂，但这是信息架构问题，本版不动（见 §4）。
- **22 个分类的 id 一经发布不变**：卡 id 形如 `${categoryId}-${slug}`，所以「挪卡」= 换 id，牵连图片、音频、老用户本地数据（见技术方案 §2）。

## 2. 需求条目

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| US-Z1 | 家长在分类页看到「小虫子」时，蜜蜂与蝴蝶在里面 | 不再出现「点小虫子找不到蜜蜂、点动物反而有」 |
| US-Z2 | 家长在「穿戴」里找得到鞋子与帽子 | 穿戴分类补齐最基础的两件 |
| US-Z3 | 家长在「学校用品」里找得到书包、在「职业」里找得到老师 | 老师不再是「家人」 |
| US-Z4 | 已经用过旧版本的家庭，升级后不会看到重复卡片 | 旧 id 的卡必须被替换而不是并列保留 |

## 3. 验收口径

1. 上表 7 张卡的 `categoryId` 与分类页归属全部改到位，且分类页计数随之变化（动物 19 / 小虫子 12 / 海洋 11 / 日常用品 12 / 穿戴 12 / 学校 13 / 职业 11 / 家人 11）。
2. 总张数仍 **809**、分类仍 **22**，`schemaVersion` 仍 1，`SEED_VERSION` 9 → 10。
3. 老用户（本地已有 v9 种子）打开新版：动物里不再有蜜蜂 / 蝴蝶 / 鱼，小虫子里出现蜜蜂 / 蝴蝶，且**不出现同名重复卡**。
4. 图片与音频跟着走：`assets/images/{新分类}/{slug}.webp` 与 `assets/audio/{新卡 id}.mp3` 都能取到，两个 manifest 同步。
5. 五道门禁全绿；新增断言能挡住「把蜜蜂挪回动物」这类回退。

## 4. 本次不做

- 不动首页分段与排版（v0.10 的四段结构不变，只是段内计数变了）。
- 不解决「认物 17 个入口 vs 字卡 2 个入口」的倒挂（留给 v0.12 的认物再分词）。
- 不重画任何图片：7 张图直接挪目录，内容不变（分类色板会与新分类不一致，属内容任务）。
- 不做收藏 / 认识标记的 id 跟随迁移：这 7 张卡若曾被收藏，升级后收藏会消失（技术方案 §5 已记为偏差 Z-3）。
