## 2. 领域建模（本版只动三处口径）

### 2.1 概念与不变量

| 概念 | 本版口径 | 不变量（门禁或测试锁定） |
| --- | --- | --- |
| 汉字学习组 | `cards.ts` 里 `CHARACTERS` 的注释分组（二十 → **二十五**） | 仅是源码可读性分段，不进数据 |
| 汉字主题组 | `characterGroups.ts` 的 `CHARACTER_GROUPS`（七 → **八**） | 每个汉字卡恰好属于一个组；双向覆盖（组表字集合 = 卡集合） |
| 诗词朝代组 | `POEM_GROUPS`（二 → **三**：`tang` / `song` / `other`） | `POEM_GROUP_BY_DYNASTY` 必须覆盖种子中出现的全部朝代；未覆盖即测试失败 |
| 数字卡数值 | 由卡片 `zh`（中文数字）**推导**阿拉伯数字，不再由排列位置推导 | `zh` 可解析为 1–100 整数；分类内解析结果两两不重复；升序排列 |
| 分类色 token | 新增 `wave` / `moss` / `denim` / `linen` | `COLOR_TOKENS`、`tokens.css`、脚本 `THEME` 三处齐备，缺一即门禁或测试失败 |

### 2.2 不建模的东西（明确排除）

- 不给 `Card` 加 `value` / `scene` / `subject` 字段：数字值可由 `zh` 推导，诗景与主体是**素材侧知识**，留在脚本，不进内容契约（加了就要迁移、要进导入导出）。
- 不把主题组写进卡片数据：沿用 v0.1.7 的「外置映射表、零迁移」决策。
- 不做内容分包 / 懒加载种子：单包 gzip 仍有 150KB 余量，与 ADR-003 的单包取向一致。

## 4. 关键设计

### 4.1 数字 1–100 精选：出图口径改造（US-C2）

现状 `cardSvg` 的 numbers 分支是 `value = index + 1`、中文取 `CN_NUMERAL[index]`（只有 一~十）。加到 28 张必然错位，且 `CN_NUMERAL` 会画成空串。

改为**按卡片中文数字推导**：

```js
// 新增纯函数（放在 prepare-images.mjs 顶层，导出给同目录测试引用）
function cnNumberToValue(zh) {
  const DIGIT = { 零: 0, 一: 1, 二: 2, 三: 3, 四: 4, 五: 5, 六: 6, 七: 7, 八: 8, 九: 9 };
  if (zh === '一百') return 100;
  if (zh.includes('十')) {
    const [head, tail] = zh.split('十');
    return (head ? DIGIT[head] : 1) * 10 + (tail ? DIGIT[tail] : 0);
  }
  return DIGIT[zh] ?? null;   // null 交由调用方抛错，绝不画成 0 或空
}
```

| 项 | 口径 |
| --- | --- |
| 入参来源 | 卡片 `zh`（`parseCards` 已把 `zh` 传给 `cardSvg`），`index` 不再参与数字推导 |
| 失败处理 | 解析为 `null` 立即抛错中止，不允许画成空白 |
| 版式 | 单位数与两位数沿用 `font-size="128"`；三位数（100）降到 `font-size="96"` 并保证不出白卡（脚本内按字符串长度分档，写清是渲染档位不是魔法数） |
| 中文名 | 下方中文直接用卡片 `zh`，删除 `CN_NUMERAL` 常量 |
| 排序 | `sortOrder` 由数组顺序决定，数组按 1 → 100 升序书写，门禁 §5.2 校验解析结果严格递增 |

新增 18 张（slug 用英文数词，`en` 与 slug 同名口径）：`eleven…twenty`、`thirty、forty、fifty、sixty、seventy、eighty、ninety`、`hundred`（zh 一百、en `one hundred`，2 词 ≤ 3 词门禁内）。

### 4.3 汉字第八主题组与覆盖校验（US-C1）

- `cards.ts` 追加注释组 二十一~二十五（各 16 字），`CHARACTERS` 241 → 321。
- `characterGroups.ts` 新增 `{ key: 'speech', name: '口语与常用' }` 排在第七组之后（第八位），并把 80 字按 §7 表落进八个组。
- 分组后计数（实现时由 `validate:content` 输出的分组表核对）：数字与量 25 / 身体与家人 55 / 自然与季节 44 / 动物与植物 38 / 方位与地点 38 / 动作与形容 44 / 生活与学习 61 / 口语与常用 16 = **321**。
- 脚本侧解析汉字组的正则是 `\{ key: '([a-z]+)', name: ...`，`speech` 合规（不含数字与连字符）。
- slug 规则：小写拼音；**与既有 241 字或相互冲突时加英文类别后缀**，沿用 `jiu-old` 先例（例：是 `shi-is`、蛇 `she-snake`、蚁 `yi-ant`、医 `yi-doctor`）。完整表见 §7，实现时照抄即可。
- 汉字卡图片不变（白卡 + 楷体单字 + 底墨线），新字零美术成本；仅受字体覆盖风险影响（§8 R3）。

### 4.5 出图主体登记与画师扩展（40 张实物卡）

| 分类 | 复用既有画师 | 需要新画的形状 |

统一约束（v0.3 沿用，写进实现检查表）：

1. 新主体一律走既有共用件 `castShadow`（落地阴影）、`CAST_TONES` 色板、`castFace`（职业人物的脸）；`CAST_INK` 只用于五官。
2. 内部坐标沿用「脚底 y = 0、身高 96」，缩放由 `cardSubject` 的 `scale` 负责。
3. 落脚线：`cardBaseY` 现按 `spec.art` 判断（sky 300 / fish·tadpole·body 236 / 其余 272）。本版给 sea 的 10 条 spec 加 `water: true` 标记，`cardBaseY` 改为「`spec.water === true` 或 art 属于水生 → 236」；`crab` / `shell` 归水底仍用 236（画面上半留白由背景的波纹带承接）。
4. **未登记主体改为抛错**：`cardSubject(slug)` 取不到 spec 或取不到 draw 函数时 `throw new Error('主体未登记：{slug}（请先在 prepare-images.mjs 的 CARD_SPECS 登记）')`，全量出图中止。这是本版最重要的一条管线加固（对应 PRD §7「不允许产出没有主体的卡」）。

### 4.6 音频增量（US-C6 发音可用）

- 无需改脚本：`prepare-audio.mjs` 按 `parseCards()` 全量枚举，已存在的条目跳过，故 `npm run prepare:audio` 只会新增 158 条。

## 11. 决策记录（ADR 摘要）

| 编号 | 决策 | 理由与被否方案 |
| --- | --- | --- |
| ADR-T1 | 数字值**由 `zh` 推导**，不给 `Card` 加 `value` 字段 | 加字段是契约变更（迁移 + 导入导出 + 管理区表单三处连锁），且家长自建卡不会填；推导逻辑放脚本，内容契约零变更 |
| ADR-T2 | 朝代三组：`tang` / `song`（含五代）/ `other`「汉魏与明清」 | 现状「非唐即宋」；改成三组映射表可扩（明、清、汉乐府、南北朝），五代维持原归属以免既有《相见欢》跳组 |
| ADR-T3 | 汉字主题组 7 → 8，单开「口语与常用」 | 虚词无可指认实物，混进「生活与学习」会让该组 61 → 77 字、一屏翻不完；组数 +1 只影响 chips 换行 |
| ADR-T4 | 主体未登记从静默空景改为**抛错中止** | 出图阶段发现「只有背景」要靠肉眼；抛错 + 门禁 V1 把它变成机器可查 |
| ADR-T5 | 新分类 `sortOrder` 追加 18–21，不插队 | 插队会让内置序号与家长已有排序冲突；主题相邻性靠命名与配色表达 |
| ADR-T6 | 数字只做 1–20 + 整十 + 一百（28 张） | 21–99 的 79 张同类图零信息增量（与 PRD D-C2 同一决策的方案侧确认） |
| ADR-T7 | 本版不引内容分包 | 预算余量尚大（174 → 200 KB 目标，硬线 350），分包会牵动 `CatalogProvider` 单例启动语义，风险大于收益 |
