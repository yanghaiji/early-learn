# 分类归属纠偏 · 技术方案（v0.11.0）

> 对应需求：`FR/v0.11/PRD-分类归属纠偏.md`。开工前确认的三条：只挪 7 张卡、老用户按内置 id 重写（PRD 决策 A）、不动首页结构。

---

## 1. 开工前事实核对

| 事实 | 数值 / 结论 | 影响 |
| --- | --- | --- |
| 卡 id 生成 | `buildObjects()` 里 `id = ${categoryId}-${slug}`、`image = assets/images/${categoryId}/${slug}.webp`（`src/data/seed/cards.ts:882-890`） | **挪卡 = 换 id**，不是改一个字段 |
| 卡所属分类 | 每类一个 `readonly Row[]` 常量，`SEED_CARDS` 末尾统一铺开（`:942`） | 挪卡 = 把 7 行从旧数组搬到新数组 |
| 图片 | `public/assets/images/animals/{bee,butterfly,fish}.webp`、`daily/{shoes,hat,backpack}.webp`、`family/teacher.webp` 共 7 个文件确实存在 | 用 `git mv` 带走，不重画 |
| 图片清单 | `public/assets/images/manifest.json` 是 `categoryId → slug[]`（21 个 key，故事不在内） | 7 个 slug 要在两个数组间搬 |
| 音频 | `public/assets/audio/{cardId}.mp3` + `manifest.json`（**659 条，key 就是 cardId**） | 7 个 mp3 要改名，清单 7 个 key 要跟着改 |
| 音频门禁 | `checkAudio()` **双向严格**：每张 `en` 非空的卡必须有同名 mp3，清单里也不能有多余条目 | 改漏一处 `validate:content` 就红 |
| 图片门禁 | `checkImagePipelines()` 只查 slug 是否在 `CARD_SPECS` 登记，与分类无关 | 挪卡不需要动 `prepare-images.mjs` |
| 老用户合并 | `mergeSeedCards()` 只按 id **增量补齐**，从不删（`catalogStorage.ts:178-193`） | 不处理 → 旧卡与新卡并列，首页出现两个「蜜蜂」 |
| 学习进度 | `progressStore` 初始化时 `repository.load()` **不传** `existingIds`（`progressStore.ts:46`） | 旧 id 的收藏/标记会成为孤儿，不显示但也不报错 |
| 种子断言 | `seed.test.ts` 锁 809 张 / 22 分类 / 每类 ≥ 8 张 | 挪卡后总数与每类下限都不变，现有断言仍成立 |

## 3. 老用户迁移（PRD 决策 A）

`SEED_VERSION` 9 → 10，并在 `mergeSeedCards()` 里「先剔除、再补齐」：

```ts
// src/data/seed/index.ts —— 与 SEED_VERSION 同处导出
export const RETIRED_SEED_CARD_IDS: readonly string[] = [
  'animals-bee', 'animals-butterfly', 'animals-fish',
  'daily-shoes', 'daily-hat', 'daily-backpack', 'family-teacher',
];
```

```ts
// catalogStorage.ts / mergeSeedCards
const retired = new Set(RETIRED_SEED_CARD_IDS);
const keptCards = doc.cards.filter((card) => !retired.has(card.id));
const cardIds = new Set(keptCards.map((card) => card.id));
// …新增分类与新卡的增量补齐不变，最后 cards: [...keptCards, ...addedCards]
```

四条口径：

1. **只在版本落后时执行**（沿用现有 `readSeedVersion() >= seedVersion` 早退）：已经升到 v10 的本地数据不会再被剔一次。
2. **只按 id 剔**，不按 slug：家长自建卡的 id 是 uid，不可能撞上这 7 个内置 id。
3. **不删家长改过的字段**：这 7 张卡被整张替换（新卡来自种子），若家长改过图或文案，改动会丢 —— 代价明确、范围只有 7 张。
4. **幂等**：重复加载不会产生重复卡（`keptCards` 去重 + `addedCards` 按 id 过滤）。

## 4. 资源迁移

七次 `git mv`（保留文件历史，而不是「删旧 + 生成新」）：

```text
images/animals/{bee,butterfly}.webp → images/insects/
images/animals/fish.webp             → images/sea/
images/daily/{shoes,hat}.webp        → images/clothes/
images/daily/backpack.webp           → images/school/
images/family/teacher.webp           → images/jobs/
assets/audio/animals-bee.mp3         → assets/audio/insects-bee.mp3
（其余 6 个 mp3 同理按新 cardId 改名）
```

两个 manifest 用一次性脚本改（放 `.tmp/`，跑完删）：`images/manifest.json` 搬 7 个 slug（保持种子顺序），`audio/manifest.json` 改 7 个 key。**不跑 `prepare:images` / `prepare:audio`**：前者会按分类色板重画、后者要 SAPI5 与 ffmpeg，两者都超出「挪目录」的范围。

## 7. 决策与偏差

| 编号 | 内容 | 理由 |
| --- | --- | --- |
| Z-1 | 老用户用「按内置 id 重写」（PRD 决策 A），不引入 `source: seed / user` 标记 | 加标记要动 `schemaVersion` 与导入导出，代价远大于收益；影响面只有 7 张卡 |
| Z-2 | 资源用 `git mv`，不重跑 `prepare:images` / `prepare:audio` | 图画的是同一件东西，重画只会让色板对、内容错；音频重生成要依赖本机音色 |
| Z-3 | 收藏 / 认识标记不做 id 跟随 | `progressStore` 不传 `existingIds`，旧 id 自然成为孤儿（不显示、不报错）；为 7 张卡引入别名迁移不划算，PRD §4 已写明 |
| Z-4 | 挪卡后 `sortOrder` 排到新分类末尾 | 新分类的顺序由数组位置决定，插在中间会让已有卡的 `sortOrder` 整体后移，反而扰动更多 |
