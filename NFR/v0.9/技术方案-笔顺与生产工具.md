### 2.2 构建脚本 `scripts/build-stroke-data.mjs`（`npm run prepare:strokes`）

- 输入：`node_modules/hanzi-writer-data/<字>.json` 与 `src/data/seed/characterGroups.ts` 的 8 组表（与 `build-pinyin-dict.mjs` 同一种「读源码表 → 生成产物」的做法）。
- 处理：只保留 `strokes` 与 `medians`（丢弃 `radStrokes` 等运行时无用字段）；按组归并；每字记录笔画数。
- 输出两个产物：
  1. `src/data/strokes/group-<key>.ts`：`export const DATA: Record<string, StrokeCharData> = { ... }`，8 个文件（`StrokeCharData = { strokes: string[]; medians: number[][][] }`，类型放 `src/data/strokes/types.ts`）。
  2. `src/data/strokes/manifest.json`：`{ "updatedAt": "...", "groups": { "numbers": ["一","二",...] }, "strokes": { "一": 1, ... } }`（321 条，约 4 KB）。
- 幂等：产物按字排序、键顺序固定、不带时间戳（`updatedAt` 只写日期），二次运行 diff 为空；与 v0.8 字典脚本同口径。
- 缺字：若某字在数据包中不存在（生僻/新增字），脚本**不中断**，在 `manifest.missing` 里列出并以非零码退出，提示「这 N 个字没有笔顺数据，需要人工确认」。

### 2.3 运行时加载 `src/data/strokes/index.ts`

- `hasStrokeData(zh)` 查 `CHARACTER_GROUP_BY_ZH`（已有的事实源），**不读 manifest**：manifest gzip 2.6 kB，进主 chunk 就把 §7.1 的「主 chunk ≤ 197.08 + 0.5」顶穿；而汉字卡与主题组本来就是同一份 321 字。两份同源由三处锁住：门禁 V3（组覆盖全部汉字卡）、V8（manifest 与卡片双向相等）、`strokes.test.ts` 的「manifest 键集合 === 组表键集合」。
- 组 chunk 只在该字首次被点开时载入；同一会话内同组复用同一个 Promise。

```ts
// 缓存只留成功路径：失败必须摘掉，否则断网那一次之后「检查网络后再试」永远重试不了
export function createGroupCache(load: (key: string) => Promise<StrokeGroupData>) {
  const cache = new Map<string, Promise<StrokeGroupData>>();
  return (key: string): Promise<StrokeGroupData> => {
    const hit = cache.get(key);
    if (hit) return hit;
    const pending = load(key);
    cache.set(key, pending);
    void pending.catch(() => {
      if (cache.get(key) === pending) cache.delete(key);
    });
    return pending;
  };
}
```

- `loadGroupByKey` 用 switch + 字面量 `import('./group-<key>')`，Vite 才切得出 8 个 chunk；未命中的 key 直接拒绝。
- `loadCharStrokeData(zh)` = 取组 + 取单字（缺字拒绝 `missing`）。`StrokePlayer` **先 await 它再 `HanziWriter.create`**，`charDataLoader` 只做 `onLoad(data)` 适配：数据失败时连 writer 都不建，回落路径比「create 后再等库报错」短一截。

### 2.4 门禁 V8（`scripts/validate-content.mjs` 追加）

| 规则 | 判红条件 |
| --- | --- |
| 覆盖 | `manifest.strokes` 的键集合与 321 张汉字卡的 `zh` **双向相等**（缺字、多余字都拦） |
| 笔画数一致 | 每字 `manifest.strokes[zh]` 必须等于卡片 `strokes` 字段；不一致即拦（数据错位会让孩子看到错误的笔数） |
| 镜像自守 | 若 `manifest.strokes` 为空或解析到的汉字卡为 0，直接失败（防「形同虚设」全通过，与 V1~V5 自守同口径） |

## 3. 笔顺页面（`StrokePlayer`）

### 3.1 位置与尺寸

- 汉字卡详情页：`card.kind === 'character' && hasStrokeData(card.zh)` 时用 `<StrokePlayer zh={card.zh} />` **替换**原来那个 `<p className="detail__char">`，位置与字号视觉连续（US-X1「在原大字位置演示」）；无数据或非汉字卡仍是原来的静态大字。
- 播放区是固定方块 `--stroke-size: clamp(120px, 36vw, 220px)`（窄屏 120px）：**未播放时方块里就是那张大字**（字号 `calc(var(--stroke-size) * 0.72)`），点开后画布接管，不出现「大字 + 空方块」两块并列，也没有布局跳动。
- 尺寸用 `getBoundingClientRect().width` 量，**变化 > 8 px 才重建** writer（库要求固定 `width/height`）；无 `ResizeObserver`（jsdom / 老浏览器）只用首帧；量到 0 时兜底 160，别让库拿到 0。
- `loading` 期间仍显示静态大字，先把数据拿到再换画布，避免白一块。

### 3.2 状态机

`idle → loading → playing → (done | stopped)`；再点回到 `playing`（重播）。

| 状态 | 按钮文案 | 行为 |
| --- | --- | --- |
| idle / done | 看笔顺 / 重播 | 载入组数据 → `HanziWriter.create` → `animateCharacter()` |
| loading | 载入中…（禁用） | 只发生一次，同组后续点击直接进 playing |
| playing | 停止 | `writer.pauseAnimation()`，已画笔画保留 |
| stopped | 重播 | `writer.animateCharacter()` 从头画 |

- 组件卸载 / 换卡时丢掉 writer 与已载数据（详情页同一路由会复用组件实例）；`ResizeObserver` 在 effect 清理里断开。
- 每轮播放带一个递增的 `runRef`：暂停后迟到的 promise 不会把按钮从「重播」改回「停止」，换卡后旧一轮也不会写状态。
- 动画参数：`strokeAnimationSpeed: 1`、`delayBetweenStrokes: 220`、`padding: 8`、`showOutline: true`；颜色从 CSS 变量读取（`getComputedStyle`：`--c-ink` / `--c-line` / `--c-primary`）以跟随主题，不写死色值。

### 3.3 减少动画

`settings.reduceMotion === true` 时：不调用 `animateCharacter`，`create` 时直接 `showCharacter: true`，按钮文案改为「显示整字」，点击只做一次淡入；并显示一句「设置里已开启减少动画，这里只显示完整字形」。测试要覆盖「reduceMotion 为真时不调用 `animateCharacter`」。

### 3.4 懒加载与体积

- `CardDetailPage` 内 `const StrokePlayer = lazy(() => import('./StrokePlayer'))`，`Suspense` 回落到**同一张静态大字**（布局不跳）。
- 预算：`StrokePlayer` + `hanzi-writer` 合一个 chunk，gzip ≤ 50 kB；8 个数据 chunk 各 gzip ≤ 60 kB；主 chunk 与 `CardAdmin` 不因此变化。
- 实测（§7.1）：`StrokePlayer` gzip 12.13 kB；主 chunk 197.56（+0.48，余量 0.02）；`daily` chunk 60.34，**超上限 0.34 kB**（数据本身 59.9，chunk 另含模块包装与许可声明头），见 §7.1 备注。

### 3.5 失败降级

| 情况 | 处理 |
| --- | --- |
| 该字无数据 | 不渲染按钮（`hasStrokeData` 为假），详情页其余部分不受影响 |
| 组 chunk 拉取失败（断网且未缓存） | 按钮回到 idle，toast 一次「笔顺数据没加载成功，检查网络后再试」；不抛错、不白屏 |
| 库初始化异常（无 DOM 尺寸等） | 同上，回落到静态大字 |
| 只读模式 | 正常可用（笔顺只读不写） |

### 3.6 样式

- 新增 `.stroke-player`（`display: grid; place-items: center; width: var(--stroke-size); height: var(--stroke-size); margin: 0 auto`）、`.stroke-player__canvas`、`.stroke-player__note`。
- 方块边框用 `--line` 一档最淡色，圆角 12 px，与详情页其它块同族；窄屏（≤ 560 px）尺寸落到 120 px 且按钮与说明上下排。

## 4. CSV 批量录入

### 4.1 解析器 `src/domain/services/csv.ts`（纯函数、零依赖）

- 支持 RFC 4180 常用子集：逗号分隔、`"` 包裹、`""` 转义、字段内换行、CRLF / LF、UTF-8 BOM 头、尾随空行忽略。
- 产物：`{ header: string[]; rows: { line: number; cells: string[] }[] }`；`line` 是**文件行号**（含表头计数），用于错误定位。
- 不支持的写法（分号分隔、Excel 的 `sep=` 头）直接报「表头不正确，请下载模板」。

### 4.2 列映射

| CSV 列 | 必填 | 映射到 | 规则 |
| --- | --- | --- | --- |
| `category` | 是 | `categoryId` | 先按分类 `id` 精确匹配，再按 `name` 匹配（去空格）；都不中 → 该行错误 |
| `kind` | 否 | `kind` | 只允许 `object` / `character`，空值为 `object`；其它值报错（诗词/故事/成语走 JSON） |
| `zh` | 是 | `zh` | 沿用 `LIMITS.ZH_MAX`；`character` 必须单字 |
| `pinyin` | 是 | `pinyin` | 必须带声调（沿用 `NEUTRAL_TONE_ZH` 豁免） |
| `en` | 是 | `en` | ≤ `EN_MAX_WORDS` 个单词 |
| `difficulty` | 否 | `difficulty` | `1` / `2` / `3`，空值 `1` |
| `tags` | 否 | `tags` | `\|` 分隔，≤ `TAG_MAX` 个、每个 ≤ `TAG_LEN` |
| `strokes` | `character` 必填 | `strokes` | `1`–`30` 整数 |
| `words` | 否 | `words` | `\|` 分隔，≤ `WORDS_MAX`，每个 ≤ `WORD_LEN` |
| `image` | 否 | `image` | 绝对路径 / `https://` / `data:`；空值填占位图路径 |

- 逐行产出 `CardInput`（不含 `id`，由 `createId` 生成，避免家长手搓 id 冲突）。
- 占位图：新增 `public/assets/images/placeholder.webp`，由 `scripts/prepare-images.mjs` 追加生成（分类色底 + 虚线框 + 「待补图」三字），预览里统计「N 张未配图」。

### 4.3 校验与整表拒绝

1. 结构与列 → 表头错误整表拒绝（不进预览）。
2. 逐行：`validateCardRules` + `cardSchema`（与入库同一套规则），收集 `{ line, field, message }`。
3. 任何一条错误存在 → **不进预览确认页**，直接弹出「共 N 行有问题」列表（最多 10 条 + 「还有 M 条」）。
4. 全部合法 → 进预览：`新增 X 张（按分类分布）· 重复 Y 张（跳过）· 未配图 Z 张`。

### 4.4 重复判定

- 口径：同一 `categoryId` 下 `zh` 相同即视为重复（与分类内「同名卡」语义一致），默认跳过，预览单列。
- 不按 `id` 判重（CSV 不带 id）；不做「有则更新」，见 PRD §4 第 6 条。

### 4.5 写入路径

- 新增 context 方法 `bulkCreateCards(inputs: CardInput[]): Promise<{ inserted: number }>` → `boot.repos.cards.bulkUpsert(inputs)` + `run()`（复用现有刷新与错误升级）。
- 写入前先建快照（来源 `csv-import`），见 §6.3。
- 成功后 toast：「已录入 X 张卡片」，并刷新分类统计（`run` 已触发 `refresh`）。

### 4.6 模板下载

- 按钮「下载 CSV 模板」：表头 + 2 行示例（一 object、一 character），UTF-8 **带 BOM** 以便 Excel 正确识别中文；文件名 `early-learn-录入模板.csv`。
- 复用 `shared/utils/download.ts` 的下载工具（新增 `downloadText` 变体，不覆盖现有 `downloadJson`）。

## 5. 上传图压缩

### 5.1 目标与档位

| 项 | 取值 |
| --- | --- |
| 原图上限 | 8 MB（`LIMITS.IMAGE_RAW_MAX_BYTES`，替代现在的 500 KB 前置拒绝） |
| 压缩后硬上限 | 150 KB（`LIMITS.IMAGE_TARGET_BYTES`），写入前校验 |
| 最长边 | 1280（`LIMITS.IMAGE_MAX_EDGE`） |
| 编码 | 优先 `image/webp`；不支持则 `image/jpeg` |
| 质量档 | 0.82 → 0.72 → 0.62 → 0.55，仍超限则边长 1280 → 1024 → 800 |

### 5.2 实现

- 纯函数（可测，放 `shared/utils/image.ts`）：
  - `fitWithin(width, height, maxEdge): { width, height }`
  - `nextAttempt(current: { edge: number; quality: number }): { edge: number; quality: number } | null`（按上表逐档推进，用尽返回 null）
  - `estimateDataUrlBytes` 已有，复用。
- 副作用层：`compressImageFile(file: File): Promise<PickedImage & { originalBytes: number; width: number; height: number; mime: string }>`：
  - `createImageBitmap(file)` 优先，不支持时回退 `<img>` + `URL.createObjectURL`；
  - `canvas.toBlob` 逐档重试，`blob.size ≤ IMAGE_TARGET_BYTES` 即停；
  - `FileReader` 转 dataURL（沿用现有实现）。

**实现回写（T-X8，2026-10-31）**：`src/shared/utils/image.ts` 已落四件纯函数 ——`fitWithin`（等比缩最长边、小图不放大、非正尺寸返回 0、细长图两侧下限 1）、`imageAttempts`（3 边长 × 4 质量 = 12 档）、`firstAttempt` / `nextAttempt`（先降质量后缩边，末档返回 null）、`withinTarget`（按 `blob.size` 判，0 字节视为编码失败）；`LIMITS` 新增 `IMAGE_RAW_MAX_BYTES` / `IMAGE_TARGET_BYTES` / `IMAGE_MAX_EDGE`，`IMAGE_MAX_BYTES` 收窄语义为「只管导入 JSON」。

两条实现口径：

- `nextAttempt` 传入**非档位值**一律返回 null（视为已用尽），而不是静默回首档 —— 否则调用方的重试循环永不终止。
- `readImageAsDataUrl` 本任务**未动**，仍按 500 KB 前置拒绝：若现在就把上限放到 8 MB 而压缩尚未接入，等于把 667 KB 的 base64 直接写进 localStorage（PRD §1.2 要修的就是这个），故放宽与压缩必须在 T-X9 同一步落地。

### 5.3 UI 与错误

- `CardForm` 图片行：选图 → 显示「压缩中…」→ 完成后显示「1.8 MB → 96 KB · 1280×960 · WebP」，旁边保留「重新选择」。
- 错误路径：原图 > 8 MB → 提示「照片太大，请先裁剪」；逐档用尽仍超 150 KB → 提示「这张图细节太多，压缩不到 150 KB，请换一张或先裁剪」，**不写入**。
- 只读模式：与现状一致，管理区整体禁用。

### 5.4 LIMITS 变更

**实现回写（T-X10，2026-10-31）**：`src/data/storage/snapshotStore.ts` 已落端口与保留策略 —— `SnapshotLabel` 六个来源 + `SNAPSHOT_LABEL_TEXT` 中文说法、`SnapshotRecord` / `SnapshotPort`（`list` / `put` / `remove`）、`SNAPSHOT_KEEP`（5）/ `SNAPSHOT_MAX_BYTES`（8 MB）、`estimateSnapshotBytes`、`createSnapshotStore({ port, now, keep, maxBytes })`：`create` 超限**不写库**、只回 `{ ok: false, reason: 'too-large', bytes }`，写库后按 `createdAt` 新在前截断到 5 份并删掉多余的。内存实现放 `src/test/snapshotPort.ts`（可注入 `list` / `put` / `remove` 失败），T-X11 面板直接复用。

三条实现口径：

- `bytes` 仍是 `JSON.stringify(doc).length`（字符数）：中文按 1 字符计，比真实 UTF-16 字节小约一半，只用来挡「单份 8 MB」这一档，不拿来当「占用空间」展示。
- 快照 `id` = `snap-<createdAt>-<序号>`，序号取写入前 `list()` 长度 + 1；排序在 `createdAt` 相同时按序号降序，避免同一毫秒连备两份时顺序不稳。
- `restore(id)` 只回 `doc`，**不校验也不写库**：`parseCatalogDocument` 与 `storage.replace` 都留给 T-X11 的恢复流程，本文件保持可在 Node 里纯测。

- IndexedDB 实现：`createIdbSnapshotPort()`，库名 `early-learn-snapshots`、版本 1、store `snapshots`（`keyPath: 'id'`，`index: createdAt`）。
- 写入前用 `JSON.stringify(doc).length` 估算 `bytes`；单份 > `SNAPSHOT_MAX_BYTES`（8 MB）时拒建并提示「内容太大，请先导出 JSON 备份」。

### 6.2 保留策略

| 项 | 取值 |
| --- | --- |
| 保留份数 | 5（`SNAPSHOT_KEEP`），超出淘汰 `createdAt` 最旧的一条 |
| 单份上限 | 8 MB（`SNAPSHOT_MAX_BYTES`） |
| 触发点 | 手动「立即备份」；自动：`bulkCreateCards`（batch）、`importBundle` merge / replace、`resetToSeed`、`restore` 前 |

### 6.3 恢复流程

1. 用户在列表点「恢复」→ `DangerConfirm` 显示「将用 <时间 · 来源 · N 张> 覆盖当前 M 张」。
2. 确认后：先 `createSnapshot(当前 doc, 'before-restore')`（失败则中止，不损失现状）。
3. `parseCatalogDocument(snapshot.doc)` 再校验一次（防旧版结构）。
4. `boot.storage.replace(doc)` → `refresh()` → toast「已恢复到 <时间> 的快照（N 张）」。
5. 学习进度不参与快照，恢复后收藏/标记保持不变。

### 6.4 降级

- 打开 IndexedDB 失败（隐私模式 / 禁用 / `SecurityError`）→ `snapshotSupport = false`：面板只显示「本机不支持快照，请用「导出 JSON」做备份」，不报错、不阻塞其它功能。
- 恢复失败（快照结构损坏）→ toast 原因，保持现状不变。

| 编号 | 决策 | 取舍 |
