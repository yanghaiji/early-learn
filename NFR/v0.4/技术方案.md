## 2. 战术设计（领域层）

### 2.1 值对象与实体

```
值对象 MarkStatus：'known' | 'unknown'           （不变量：只有两态，取消标记 = 键不存在）
值对象 RecentEntry：{ cardId: CardId, at: ISO8601 }（不变量：同一 cardId 全文档唯一）
实体   ProgressDocument（聚合根，本机唯一一份）
  标识 schemaVersion: 1
  属性 favorites: CardId[]                        （顺序 = 收藏时间倒序，最多全部卡片数）
        recent:   RecentEntry[]                   （≤ 24，队头最新）
        marks:    Record<CardId, { status, at }>   （只存已标记的）
  生命周期 空文档 → 交互累积 → 加载时按现存卡片 id 剪枝 → 重置清空
  不变量
   - favorites 去重、recent 去重、marks 的键唯一
   - 三个集合内的 cardId 必须存在于当前 catalog（不满足即剔除）
   - recent.length ≤ LIMITS.RECENT_MAX
```

不在聚合内的事：出题随机性、复习排序 —— 属领域服务，便于测试与替换规则。

### 2.2 领域服务（纯函数，无浏览器依赖）

`src/domain/services/progress.ts`

| 函数 | 契约 |
| --- | --- |
| `toggleFavorite(doc, cardId, at)` | 在则移除、不在则 unshift；返回新文档（不可变） |
| `touchRecent(doc, cardId, at)` | 去重后 unshift，截断到 `RECENT_MAX` |
| `setMark(doc, cardId, status \| null, at)` | `null` 删键（支持「再点一次取消」） |
| `prune(doc, existingIds: Set)` | 三处集合按现存 id 过滤；**在仓储加载阶段调用一次** |
| `knownCount(doc, existingIds)` / `unknownCount(...)` | 统计只算仍存在的卡，避免删卡后数字虚高 |
| `buildReviewQueue(doc, cards, limit)` | 取 `unknown` → 按 `difficulty` 升序 → 同级稳定随机 → 截断 `REVIEW_ROUND_MAX` |

`src/domain/services/quiz.ts`

| 函数 | 契约 |
| --- | --- |
| `buildDeck(cards, progress, size, rng)` | 正确项来源 = `recent ∪ favorites ∪ marked`，不足从全库随机补；同局不重复 |
| `buildQuestion(card, pool, rng)` | 1 正确 + `QUIZ_OPTIONS - 1` 干扰；**干扰优先同 `categoryId`**，不足全库补；输出顺序打乱 |
| `pickLangOptions(mode)` | `zh` → `SpeechLang='zh-CN'`；`en` → `'en-US'` |

`rng` 一律作为参数注入（默认 `Math.random`），保证单测可确定性重放——这是出题类逻辑唯一可靠的测法。

### 2.3 仓储端口

`src/domain/ports/repositories.ts` 追加：

```
ProgressRepository
  load(): ProgressDocument                 // 永远返回合法文档，脏数据 → 空文档 + corrupted 留痕
  save(doc): void                          // 存储不可用时静默失败（会话内仍有效）
  clear(): void
  isPersistent(): boolean                  // UI 据此决定是否提示「不会保存」
```

### 2.4 发音端口扩展

`src/domain/ports/speech.ts` 仅新增可选字段与一个辅助类型：

```
SpeakOptions { rate?: number; cardId?: CardId }   // cardId 存在 = 允许尝试预录音频
SpeakMode  = 'auto' | 'audio-first'               // 本版固定 audio-first，留位不实现
```

既有调用方（`useSpeech`）把 `card.id` 传进来即可，旧签名调用者不受影响。

## 4. 关键实现设计

### 4.1 音频生成管线（`scripts/prepare-audio.mjs`）

1. 解析种子得到 `{ cardId, en }` 全量（复用 `validate-content.mjs` 已有的正则解析口径，避免两套真相）。
2. 写一个 PowerShell 子脚本：`Add-Type -AssemblyName System.Speech`，`SelectVoice('Microsoft Zira Desktop')`，`Rate=-1`（约 0.9×，幼儿友好），逐条 `SetOutputToWaveFile(.tmp/audio/{id}.wav)` + `Speak(en)`。
3. 每条 `ffmpeg -i wav -codec:a libmp3lame -b:a 32k -ac 1 -ar 22050` → `public/assets/audio/{id}.mp3`。
4. 产出 `public/assets/audio/manifest.json`：`{ [cardId]: 'assets/audio/{id}.mp3' }`。
5. 中间 WAV 只落 `.tmp/audio/`，结束后清空（规约第 1 条）。
6. 缺 ffmpeg 或缺 Zira 时报**明确错误并中止**，不产出半套资源。

> 幂等：已存在的 mp3 默认跳过，`--force` 才重生成；单条文本为空或全标点 → 跳过并记入问题清单（不静默）。

### 4.2 预录音频适配器（行为规格）

```
speak(text, 'en-US', { cardId, rate })
  ├─ cardId 在清单内 → playAudio(file, rate)
  │     ├─ 'ended'                     → resolve（真出声）
  │     ├─ 'error' / load 超时 3s      → 记原因 → fallback.speak(text,'en-US',{rate})
  │     └─ fallback 也失败             → SpeechUnavailableError（沿用 v0.3.3 分类文案）
  └─ 不在清单内 → 直接 fallback.speak(...)

speak(text, 'zh-CN', ...) → 始终走 fallback（本机有 3 个本地中文音色，成本不划算）
cancel() → audio.pause() + currentTime=0 + fallback.cancel()，并推进 generation 令牌
hasVoice('en-US') → 清单非空即 true（音频能出声）；否则回落 fallback 判定
isSupported() → fallback.isSupported() || 清单非空
```

- 全站**共享一个** `Audio` 实例，天然避免两层声音叠加；重入时先 `pause` 再换 `src`。
- `playbackRate = rate` 对齐语速设置（0.6/0.8/1.0/1.2）。
- 清单懒加载：**首次英文朗读**时 fetch 一次，pending 期间同页重复点击共享同一请求（单飞）；失败即缓存空集，不再打网络。
- iOS/Safari 自动播放：清单加载与首次播放都必须发生在用户手势内才可靠 —— 见 §6 风险 R2。

### 4.3 连播状态机

```
idle --点「连播」（手势内）--> warming（在手势内对共享 Audio 做一次静音解锁 / 或立即朗读首句）
warming --> reading : await speak(...)
reading --onend 成功--> waiting(2000ms) --到下一张--> reading
reading --朗读失败--> stopped + Toast 原因（不静默跳张）
任意状态 --用户点停止 / 手动翻页 / 路由离开 / visibilitychange=hidden--> stopped
到达该分组（或该分类）最后一张 --> stopped + Toast「这一组看完啦」（不循环）
```

用 `speak()` 返回的 Promise 作为「读完」信号（v0.3.3 已保证 resolve/reject 语义，本版让它回报「到底有没有出声」），不另起计时器猜朗读时长。

实现口径（M-D 回写）：

- 控制器（队列、下标、定时器）放**模块级**：`/card/a` → `/card/b` 是同组件实例换 props，而卡片 → `/favorites` 再回来是销毁重建，放 `useState` 会哪一种都活不过一次跳张；组件只用一个 `running` 镜像，靠 `runningListeners` 订阅同步（否则末位卡自动播完时按钮还停在「停止连播」）。
- 单一驱动入口：详情页挂上卡片时调 `notifySlideshowCard(cardId)` —— 先读这张（手势内同步派发首句，见风险 R2），`speak` resolve 为真后才排 2s；定时器到点只 `goCard(next)`，跳转后重挂再进 notify。两边都排程会重复跳张。
- 「换卡」与「离页」分清不了，由页面 effect 的挂载/销毁维护 `markDetailPageAlive`：定时器到点时若页面已不在，按「离开详情页」中断，不得把用户拽回卡片流。
- 朗读不可用的两道防线：① 页面发现 `enabled` 在播放中变 false 就立即停并给原因；② `speak` resolve 为假（没出声）时状态机自己 halt，保证不「静默地一张张跳过」。

### 4.4 复习与出题

- 复习队列每次进入 `/review` 时按当时 `marks` 现算（不持久化队列），退出即丢——幼儿场景不需要「断点续练」，且避免状态与标记不一致。
- 游戏答错：把正确项 `highlight` 并播它的发音，同题允许再选一次；**不判负、不计分**，10 题走完只说「这一局玩完啦」。
- 出题前探测：`speechSupported &&（清单有该卡 || hasVoice(lang)）`，不满足则在 `/quiz` 首页显示不可用原因与处置建议，不进题目（对应 US-A5 最后一条）。

### 4.5 存储与隐私

- 进度键独立于 catalog：`early-learn:v1:progress`，`schemaVersion: 1`，不进 `ExportBundle`（`appVersion` 字段与内容口径不变）。
- 加载即剪枝：`load()` 内用当前 catalog 的 id 集合过滤，删卡不留破引用；`isPersistent()` 在 `localStorage.setItem` 探测失败时为 false，store 据此在首次交互时提示一次。
- 「清除学习进度」放管理区数据页签，走现有 `ParentGate` + `DangerConfirm`，只删 `progress` 键。

## 5. 测试策略

| 层 | 框架 / 环境 | 覆盖点 | 必须绿的标准 |
| --- | --- | --- | --- |
| domain | Vitest 纯函数 | 三个集合操作去重截断、`prune`、`buildReviewQueue` 排序与上限、`buildQuestion` 同分类优先与补齐、rng 注入下的确定性 | 分支覆盖 ≥ 90%（纯逻辑无 mock 成本） |

| features | Testing Library | 详情页按钮 `aria-pressed` 与 Toast、收藏空态、复习 M=0 直连 URL、连播四类中断、游戏答错无负面反馈、首页未被新增块挤出主体 | 复用现有 `app.test.tsx` 装配方式 |

## 6. ADR 与风险

### 决策摘要

| 编号 | 决策 | 取舍理由 |
| --- | --- | --- |
| ADR-P1 | 英文发音改为**自带音频优先**，不再把「设备有没有音色」当外部前提 | 已部署且客户端不可控，代码侧优化（v0.3.3）已到极限；只有自带资源能保证「点了必出声」。代价 +约 2.5–4MB 静态资源 |
| ADR-P2 | 音频按 `cardId` 定名 + `manifest.json` 清单，**不给 `Card` 加字段** | 与 ADR-005 图片策略同构、真人录音同名即换、零数据模型变更零迁移；不用 manifest 的话每次自建卡都要吃一次 404 往返与 console 噪音 |
| ADR-P3 | 进度独立切片存本机，**不进导出包** | 进度是「这个孩子」的数据，内容包是「这套教材」的数据，混在一起会导致导入他人内容时覆盖错标记；也守住「数据不出设备」的隐私边界 |
| ADR-P4 | 复习队列只按「标记为不认识」这一条硬规则，不做遗忘曲线/自适应难度 | 幼儿内容量小（501），可解释的简单规则胜过黑盒；后续换算法只替 `buildReviewQueue` |
| ADR-P5 | 复习/游戏/收藏**不加家长门**，只有清除进度要门 | 这些是给孩子点的主用途，加门即挡住主流程；与 v0.1「管理入口加门」的原意一致（门是给破坏性操作用的） |
| ADR-P6 | 连播到末尾**不循环**，切后台即停 | 循环播放对幼儿是「停不下来的屏幕」，且耗电耗流量；停住并提示符合「注意力短」的产品前提 |

### 风险

| 编号 | 风险 | 处置 |
| --- | --- | --- |
| R1 | SAPI 合成音质偏机械，家长可能嫌「不好听」而觉得还不如 TTS 网络音色 | 保留「音频失败即回退 TTS」；PRD §4.1 明确写出音质预期与同名替换路径，不在文档里承诺「真人音质」 |
| R2 | **iOS Safari 对非手势内 `audio.play()` 的限制**：连播第二张之后可能被拦成静音（和这次英文按钮同一类静默问题） | 首次播放必须在点击手势内完成（点「连播」即解锁共享 Audio 实例）；仍被拦时 `play()` reject → 回退 TTS 并停连播、明确提示，绝不静默跳张 |
| R3 | 501 条 mp3 体积失控或 CI/其他机器没有 Zira/ffmpeg 导致复现不出 | 内容门禁校验体积上限；脚本缺工具时明确报错中止而非产半套；生成物随仓库提交（产物入库，构建机不需要 TTS） |
| R4 | 进度键让 localStorage 更接近配额（现状图片 dataURL 已有风险） | 进度本身极小（约 60KB）并复用 `STORAGE_WARN_BYTES` 告警；上传照片压缩属 v0.6，本版不夹带（PRD §6 已列） |
| R5 | 出题随机导致同一局出现两张几乎一样的图（动物识别度问题） | 干扰项按 `categoryId` 分组抽取但不限物种；若后续需求方反馈混淆，再按 `tags` 进一步分散（本版留接口不留实现） |
| R6 | 范围偏大（8 个用户故事）导致半成品交付 | 按 §1.4 四个里程碑串行，每个里程碑独立可交付、门禁全绿可发布；M-C/M-D 若被砍不影响 A 组效果 |
