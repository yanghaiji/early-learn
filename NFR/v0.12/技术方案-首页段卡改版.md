## 2. 设计

### 2.1 数据层：`categoryGroups.ts` 重写为 7+1 段（T-Q1）

```ts
export interface CategoryGroupSpec {
  id: string;          // plants / things / people / nature / character / poem / story / more
  name: string;        // 段卡标题
  hint: string;        // 段卡副句
  cover: string;       // 段卡封面（复用现有分类封面路径，零新图）
  ids: readonly CategoryId[];
}
```

- 原 `object` 段的 17 个 id 拆成 `plants`(5) / `things`(5) / `people`(4) / `nature`(3)；
  `character` / `poem` / `story` 保留原 id 与成员，各加 `cover` 字段。
- `FALLBACK_GROUP`（`more`）不变；`groupCategories()` 逻辑不变（空组过滤、组内按清单排序）。
- 新增 `isGroupId(raw: string): boolean` 与 `findGroup(raw: string)` 供段页校验（`more` 也算合法）。
- **决策 Q-1**：段是展示层静态清单，不给 `Category` 实体加 `groupId` 字段、不动
  `schemaVersion` / `SEED_VERSION`——与 v0.10「归类不加字段」同一口径；家长自建分类
  自动落 `more`，不会被改版吞掉。

### 2.2 首页：段卡网格（T-Q2）

- `HomePage.tsx`：删 `RAIL_GROUPS` 双轨渲染，sections 一律渲染**段卡**（`GroupCard` 新组件，
  放 `categories/ui/GroupCard.tsx`）。
- `GroupCard`：`Link` 到 `/group/:id`，结构照 `CategoryTile` 竖卡（图上文下 + 右下张数角标），
  类名 `.group-card`；可访问名「段名 N 张卡片」。角标数字 = 段内分类张数之和；
  副句显示「M 个分类 · hint」。
- 网格 `.grid-groups`：360 两列、≥720 三列、≥1200 四列（与 `.grid-cats` 同一套断点写法）。
- 分龄 2 大卡、hero 顶栏、底部按钮行全部不动。
- `CategoryTile` 的 `row` 变体失去唯一调用方 → 删 `row` prop（决策 Q-2：不留死代码；
  `row` 是 v0.10 新加、只有 rail 段在用）。

### 2.3 段页 `/group/:groupId`（T-Q3）

- 新 `GroupPage.tsx`（`categories/ui/`），仿 `AgePage`：非法 id 空态、顶栏返回、
  「N 张卡片 · M 个分类」副标题、`grid-cats` + `CategoryTile` 列表。
- `more` 段：列全部未归段分类；为空时给空态「家长还没有新建分类」。
- **决策 Q-3**：`GroupPage` 静态 import（与 `AgePage` 同侧）——它是首页点击的第一跳，
  lazy 会让每次进段都等 chunk；体积增量主要是复用件，估算主 chunk gzip +0.3~0.6，
  余量 2.00 足够。

### 2.4 封面重绘 colors / shapes（T-Q4）

- `prepare-images.mjs` 的 `coverSvg()` 前加两个特判分支（仿 `poemCoverSvg` 模式）：
  - `colorsCoverSvg()`：6 个等距色圆（红橙黄绿蓝紫，取 `COLOR_HEX`）+ 现有背景；
  - `shapesCoverSvg()`：圆 / 三角 / 方 / 星 / 心形一排 + 现有背景。
- 出图：删 `public/assets/images/covers/colors.webp`、`shapes.webp` 两文件，
  跑 `node scripts/prepare-images.mjs --only=colors` 与 `--only=shapes`（不带 `--force`）——
  卡图已存在全 skip，只补两张缺失封面，`manifest.json` 重写但内容不变。
- **决策 Q-4**：不登记 16 个 colors/shapes slug 进 `CARD_SPECS`——特判分支与
  `cardSvg()` 既有特判同构，登记反而会让通用封面路径产出色块卡（错误主体）。

## 3. 决策台账

| 编号 | 决策 | 理由 | 否决的备选 |
| --- | --- | --- | --- |
| Q-1 | 段清单放 `categoryGroups.ts` 静态常量，不加实体字段 | 动 `Category` 要升 `schemaVersion` 牵连导入导出，v0.10/v0.11 两次同口径 | 给分类加 `groupId` |
| Q-2 | 删 `CategoryTile` 的 `row` 变体 | rail 横卡是 `row` 唯一调用方，改版后成死代码 | 留着以防回退（git 里都有） |
| Q-3 | `GroupPage` 静态 import | 首页第一跳不能等 chunk；增量 <1 kB 在预算内 | lazy（省不了多少、多一次等待） |
| Q-4 | 封面走 `coverSvg()` 特判分支，不登记 slug | 与 poem/idiom 封面同构；登记 slug 会让卡图路径被污染 | 把 red/blue 加进 `CARD_SPECS` |
| Q-5 | 诗文段封面用 `idioms.webp`（150 张是段的主体量） | 段封面应代表段内最大头 | `poems.webp`（山水压字，缩到段卡尺寸后发灰） |
