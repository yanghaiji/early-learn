## 2. 领域建模

### 2.1 概念与不变量

| 概念 | 本版口径 | 不变量（门禁或测试锁定） |
| --- | --- | --- |
| 成语卡 | `kind = 'idiom'`，`categoryId = 'idioms'`，`en` 恒为空串 | `zh` 恰好 4 字；`en === ''`；`pinyin` 带调号 |
| 释义 | `meaning`，6–90 字 | 必填；门禁下限 6（词表实测 6–34 字，见 PRD §13） |
| 例句 | `examples`，2–3 条、每条 ≤ 50 字 | 必填；每条非空 |
| 近义 / 反义 | `synonyms` 1–3 个、`antonyms` 0–3 个 | 每个词恰好 4 字（`fourCharWord`） |
| 出处 | `citation`，≤ 40 字 | 必填；展示格式 `出处 · {citation}` |
| 成语主题组 | `IDIOM_GROUPS`（5 组）+ `IDIOM_GROUP_BY_ID`（`idioms-<slug>` → 组 key） | 双向覆盖：每组恰好 30 条，无漏组、无 stale 项 |
| 意象件 | 素材侧知识：`IDIOM_PROPS`（150 条 slug → 各 2 件实物）+ `IDIOM_MOTIFS`（78 件实现） | 每张成语卡必须登记，且不超过 2 件；每个意象件名必须在 `IDIOM_MOTIFS` 有实现 |

### 2.2 不建模的东西（明确排除）

- 不给 `Card` 加 `groupId` 字段：分组是展示分组，沿用「外置表 + 零迁移」的既有决策（与汉字主题组、诗词朝代组同构）。
- 不用 `tags` 承担分组：家长可编辑标签，用它做分组会在编辑后静默失组（PRD §13 第 1 条）。
- 不做近义 / 反义词条跳转、不做典故长文、不做成语英文：均属 PRD §9 明确不做项。
- 不给成语做预录音频：中文点读走既有 WebSpeech，`assets/audio/` 与 manifest 一字不改。

## 4. 关键设计

### 4.1 类型与字段（扩契约，不升 schemaVersion）

```ts
// entities/card.ts
export type CardKind = 'object' | 'character' | 'poem' | 'story' | 'idiom';
export interface Card {
  // …既有字段
  meaning?: string;      // 释义 6–90 字
  examples?: string[];   // 2–3 条，每条 ≤ 50 字
  synonyms?: string[];   // 1–3 个四字成语
  antonyms?: string[];   // 0–3 个四字成语
  citation?: string;     // 出处 ≤ 40 字
}
```

- 全部可选：旧卡片与旧导出零改动，`schemaVersion` 保持 1。
- `en` 由 Zod 的 `min(1)` 放宽为 `trim()`，非空要求下沉到 `validateCardRules`：`kind !== 'idiom' && !en` 才报错。这样「结构合法、规则驳回」的分工与诗词、故事一致。

### 4.2 分组表（与故事同构，不用 tags）

```ts
export const IDIOM_GROUPS: readonly IdiomGroup[] = [
  { key: 'idiom-fable', name: '寓言故事' },
  { key: 'idiom-study', name: '学习求知' },
  { key: 'idiom-moral', name: '品德修养' },
  { key: 'idiom-nature', name: '自然景物' },
  { key: 'idiom-life', name: '生活常理' },
];
export const IDIOM_GROUP_BY_ID = new Map(
  IDIOM_SOURCES.flatMap(([key, rows]) => rows.map((row) => [`idioms-${row.slug}`, key] as const)),
);
```

- 组 key 带 `idiom-` 前缀：`nature` / `life` 这类裸词与汉字组 key 撞名，`ALL_GROUP_NAMES` 是跨分类合并的一张表，重名会让中文/故事的 chips 串组（首次实现踩到，typecheck 阶段发现）。
- `groupOf(card)` 的 idiom 分支返回 `IDIOM_GROUP_BY_ID.get(card.id)`，取不到返回 `undefined`（与其它 kind 的空值语义一致，页面按「全部」处理）。
- 组名进 `ALL_GROUP_NAMES`：分类页 chips 由 `groups` 计算得出，无需新 UI 代码。

### 4.4 分类页与详情页

分类页零结构改动：成语组自动出现在 `groupOf` 的 chips 里，150 张按 `PAGE_SIZE=12` 分 13 页，每组 30 张分 3 页。

详情页新增 `detail--idiom` 修饰类（不复用 `detail--poem`，避免诗词的字体与行高污染）：

```tsx
function speechTextOf(card: Card): string {
  if (card.kind === 'idiom') return card.meaning ? `${card.zh}，${card.meaning}` : card.zh;
  return card.lines && card.lines.length > 0 ? card.lines.join('') : card.zh;
}
const showChinese = mode !== 'en' || isIdiom;   // 无英文：英文模式下仍显示中文
```

- 结构：标题 + 拼音 → `.detail__idiom`（释义 / 例句「例」徽标 / 近义 chip / 反义 chip / 出处）→ 动作区。
- English 按钮在 `isIdiom` 时整块不渲染（不是 disabled），避免「点了没声」。
- 图片区让位：`.detail--idiom .detail__stage { flex: 0 0 auto; height: clamp(132px, 23dvh, 210px); min-height: 0 }`，图块用 `height:100% + width:auto + aspect-ratio:1/1` 得出正方形（不用 `cqw/cqh`，见 §11.2 偏差 4）；释义与例句优先占位，内容超出时 `.detail` 自身 `overflow-y: auto` 兜底。
- 字号按 PRD §7：释义 `clamp(17px, 2.3vh, 20px)`、例句 15px、出处 13px 灰。

### 4.5 管理区

- 类型 chip 追加「成语」；选中时若当前分类不在列表则自动切到 `idioms`（与诗词、故事同一写法）。
- 表单：成语（`maxLength=4`）、拼音、释义（`maxLength=90`，带字数计数与 6–90 提示）、例句（一行一条）、近义（逗号分隔）、反义（可空）、出处（`maxLength=40`）。
- 英文 Field 在 `kind === 'idiom'` 时不渲染；提交时 `en: ''`，表单里残留的英文不会落库。
- 即时校验与 `validateCardRules` 同源：四字、释义必填且 ≥ 6 字、例句 2–3 条、近反义四字、出处必填。

### 4.7 水墨四字卡出图（实物意象件）

| 项 | 口径 |

## 5. 门禁与校验扩展（`validate-content.mjs` 两条新增 + 逐卡规则）

| 编号 | 新增校验 | 报错口径 |
| --- | --- | --- |
| V6 | **成语意象件登记**：每个 `idioms` 卡 slug 必须在 `IDIOM_PROPS` 登记 1–2 件（本版实际 2 件），每件必须在 `IDIOM_MOTIFS` 有实现；并自守「`IDIOM_PROPS` / `IDIOM_MOTIFS` 不能解析为空」 | `成语 {id} 未登记意象件…` / `成语 {id} 登记了 n 件意象（最多 2 件）` / `成语 {id} 的意象件 {motif} 未在 IDIOM_MOTIFS 中实现` |
| V7 | **成语分组双向覆盖**：`IDIOM_GROUP_BY_ID` 必须覆盖全部 150 张卡、每组恰好 30 条、无重复无遗漏 | `成语 {id} 没有分组` / `分组 {name} 应为 30 条（实际 n 条）` |
| — | **逐卡成语规则**：四字；释义 6–90 字；例句 2–3 条、每条 8–50 字；近义 1–3 个、反义 0–3 个且均为四字；出处 ≤ 40 字；难度 1–3 | `成语 {id} …` |

另加计数自守：成语条数必须 150、组数必须 5，解析结果为空即失败（防止正则失配让门禁默认全通过）。既有校验全部保留，合计行改为 **809 张 / 22 个分类 / 659 条音频**。

## 10. 决策记录（ADR 摘要）

| 编号 | 决策 | 理由与被否方案 |
| --- | --- | --- |
| ADR-I1 | 分组用**内置表**，不写 `tags[0]`（与原 PRD 相反） | 全站既有约定是「分组由外置表决定，不写进卡片数据」；写进 `tags` 会在家长编辑后静默失组，且与分页两套导航打架 |
| ADR-I2 | 分类色复用 `denim`，不新增 token | 新增 token 是六处同步（`COLOR_TOKENS` / Zod / CSS 变量 / `categories.ts` / 脚本 `THEME` / 文档），成语属水墨系，`denim` 靛色足够表达；代价是 `jobs` 与 `idioms` 同色，靠名称与排序区分 |
| ADR-I3 | 成语排除听音选图（`quizPool`） | 卡面就是四个字，出题等于把答案印在选项上；在出题池一层排除，页面零特判 |
| ADR-I4 | 本版不做种子分包 | gzip 205.63 KB 距硬线 350 KB 尚远；分包会牵动 `CatalogProvider` 单例启动语义，风险大于收益 |
| ADR-I5 | 释义下限取 6 字（不是 PRD 原写的 20） | 已确认的 150 条词表实测 6–34 字；短释义更适合 4–6 岁照读，把门禁调到词表实际区间，避免「门禁与内容互相打架」 |
| ADR-I6 | 卡面只画 2 件实物意象 + 四字，不写释义 | 320px 宽下小字必糊；释义在详情页有 17px 以上的位置。首版曾用「14 类意境」概括，v0.6.1 按需求方反馈改为实物意象（ADR-I7） |
| ADR-I7 | 卡面主体必须是成语里真实存在的物，不用「语义相近的意境」 | 意境方案下守株待兔 =「房子 + 树」、多条成语共用同一张书桌；改为「每条成语 2 件实物 + 可复用件库（78 件）」后，新增成语只加数据与件名。代价是件库需要逐件过辨识度（见 §4.7） |

### 11.2 与方案的偏差

四处偏差，均已回写到 PRD §13：

1. **分组机制**：内置表 `IDIOM_GROUP_BY_ID` 代替 `tags[0]`（ADR-I1）。
2. **释义下限**：6 字代替 20 字（ADR-I5）。
3. **四字卡构图（v0.6.1）**：从「14 类意境」改为「每条 2 件实物意象」，`IDIOM_SCENES` + `idiomSceneMarkup` 由 `IDIOM_PROPS` + `IDIOM_MOTIFS` 取代。
4. **详情页图块尺寸（v0.6.1）**：`min(100cqw,100cqh)` + `container-type:size` 在 Chrome 下把 `100cqh` 解析成 0（图被压成 2px），改为 stage 定高 + `height:100%; width:auto; aspect-ratio:1/1`；`@supports (width:1cqw)` 兜底块一并删除。

其余按方案落地。
