## 1. 决策记录（ADR-S）

### ADR-S1 故事复用 `Card` 实体，不新建 `Story` 聚合

- **结论**：`CardKind` 增加 `'story'`，故事内容挂在 `pages: { text, image }[]` 与 `moral` 上。
- **理由**：列表、搜索、分页、组筛选、导入导出、重置、只读降级、图片占位全部已围绕 `Card` 建好；新建实体意味着两套仓储、两套校验、两套导入计划，收益为零。
- **代价**：`Card` 字段继续膨胀（已有诗词 4 个字段）。以注释分区 + Zod 可选字段控制，可接受。
- **被否决方案**：独立 `stories` 数组存进同一个文档（会让「分类内卡片数」「导入合并」「悬空引用修复」出现第二套口径）。

### ADR-S2 新增字段全部可选，`schemaVersion` 保持 1

- **结论**：`pages` / `moral` 可选，不改迁移链、不动 `SCHEMA_VERSION`。
- **理由**：老数据缺字段仍能通过 `catalogDocumentSchema`；新数据在旧版客户端会因 `kind` 枚举不识别而被拒绝（可接受的单向兼容）。
- **代价**：旧版本应用读到新导出文件会报「结构异常」，属版本前向不兼容，文档已声明。

### ADR-S3 故事配图由 `card.image` 显式给出，不靠运行时拼路径

- **结论**：种子构建时只写 `card.image = assets/images/stories/{slug}/cover.webp`（综合图）；`pages[i].image` 自 v0.2.2 起不再写入。
- **理由**：导入/导出/迁移时路径必须自洽；家长自建故事可取任意路径或留空（走占位）。
- **被否决方案**：运行时按 `card.id` 拼路径（自建卡与管理区改名会错位）；把综合图路径拆成「目录 + 文件名」两个字段（多余状态）。

### ADR-S4 分组表独立于卡片数据（延续 v0.1.7 决策）

- **结论**：`src/data/seed/storyGroups.ts` 导出 `STORY_GROUPS` 与 `STORY_GROUP_BY_ID`，由组合根注入 `groupOf`。
- **理由**：`mergeSeedCards` 只按 id 差集补卡、不补字段；分组写进卡片会让老用户的 50 个故事全部「未分组」。
- **代价**：新增故事必须同步分组表，内容门禁做双向校验兜底。

### ADR-S5 阅读器独立成页，不塞进 `CardDetailPage`

- **结论**：新增 `/story/:cardId` 路由与 `StoryReaderPage`。
- **理由**：详情页是「单屏三段式（图/词/按钮）」布局，阅读器要「一页一图一句 + 大翻页区 + 进度点」，两者空间诉求相反；塞在一起会让详情页 CSS 变成条件分支地狱。
- **代价**：多一次导航（详情 → 阅读器），用「1 次点击」换布局清晰，符合 PRD S-G1。

### ADR-S6 插图沿用程序化 SVG，不引入 AI 生成

- **结论**：`scripts/prepare-images.mjs` 增加 `STORY_SCENES`（18 个背景模板）与 `STORY_SUBJECTS`（98 个主体 key，其中小蝌蚪为矢量绘制），480×360 / q78 输出。
- **理由**：AI 逐张生成成本与额度不可控（历史出现 code 112），且风格一致性无法保证；程序化模板可一键重绘、零授权。
- **代价**：画面为扁平插画风，后续换实拍/AI 只需同名同路径覆盖。

### ADR-S7 一个故事一张综合图，阅读不翻页

- **结论**：故事页一次展示全部 4–8 段正文 + 1 张综合图（`cover.webp`），取消页码、翻页按钮、滑动与圆点；`?page=` 参数忽略。
- **理由**：需求方反馈「故事在一页 配一个综合的图就行」——6 页翻页把一个短故事切得太碎，家长还得边讲边点，反而打断叙事；单页看完更贴近讲故事的场景。
- **插图聚合**：仍保留每段的 `scene`/`subject` 作为**分镜信息**，出图时按「首次出现的场景作背景 + 全书主体去重排序（最多 3 个）」合成一张图：主角最大居中，配角分列两侧。
- **被否决方案**：只保留封面旧图（带书脊/内框，像封面而不是画面）；逐页配图（即 v0.2.0 做法，300 张图 + 一套翻页交互，收益不匹配）。
- **代价**：一个故事内的多个场景（如屋内 → 森林 → 屋内）只能取开场场景，画面是「意象集合」而非严格剧情图；文档已声明。

## 2. 数据模型

```ts
export type CardKind = 'object' | 'character' | 'poem' | 'story';

export interface StoryPage {
  /** 一段话，≤ LIMITS.STORY_PAGE_TEXT_MAX；6 段连成一个故事 */
  text: string;
  /** 兼容 v0.2.0 旧数据：分页插图路径，新种子不写 */
  image?: string;
}

export interface Card {
  // …v0.1 字段
  /** 仅 kind=story：故事段落（4–8 段），同一页展示 */
  pages?: StoryPage[];
  /** 仅 kind=story：一句寓意，正文下方与详情页展示 */
  moral?: string;
}
```

常量（`domain/constants.ts`）：

| 常量 | 值 | 用途 |
| --- | --- | --- |
| `LIMITS.STORY_PAGES_MIN` | 4 | 段数下限（管理区校验） |
| `LIMITS.STORY_PAGES_MAX` | 8 | 段数上限 |
| `LIMITS.STORY_PAGE_TEXT_MAX` | 60 | 单段文字上限（种子自律 ≤ 30） |
| `LIMITS.STORY_MORAL_MAX` | 60 | 寓意上限 |

Zod 扩展：

```ts
storyPageSchema = z.object({
  text: z.string().trim().min(1).max(LIMITS.STORY_PAGE_TEXT_MAX),
  image: nonEmpty.optional(), // 旧数据兼容，新种子不写
});
cardSchema = z.object({
  kind: z.enum(['object', 'character', 'poem', 'story']),
  pages: z.array(storyPageSchema).min(0).max(LIMITS.STORY_PAGES_MAX).optional(),
  moral: z.string().trim().max(LIMITS.STORY_MORAL_MAX).optional(),
  // …
});
```

> `pages` 允许 `min(0)`：结构校验不因空数组失败，跨字段规则由 `validateCardRules` 给出中文提示。

## 4. 故事页设计（一页读完）

**窄屏（< 780px）单列**

```
┌────────────────────────────────────────────┐
│ ←  三只小猪                      6 段    │  topbar（48px 返回）
├────────────────────────────────────────────┤
│  ┌────────────────────────────────────┐   │  严格 4:3，宽 min(100%, 58vh) 居中
│  │  综合插图 480×360                   │   │  点图 = 读整篇
│  └────────────────────────────────────┘   │
│  sān zhī xiǎo zhū · Three Little Pigs      │  meta
│  猪妈妈对三只小猪说：你们长大了……         │  段落 1
│  ……（共 6 段，可滚动）                      │
│  做事要认真，结实的房子才挡得住大风。      │  moral
│  [读整篇]              [返回故事详情]      │  ≥ 48px
└────────────────────────────────────────────┘
```

**宽屏（≥ 780px 且高 ≥ 520px）两栏**

```
┌──────────────────────────────────────────────────┐
│ ←  三只小猪                                6 段   │
├──────────────────────────┬───────────────────────┤
│  ┌────────────────────┐  │ sān zhī … · Three Pigs│
│  │  综合插图 4:3       │  │ 猪妈妈对三只小猪说……    │
│  │  占满左栏            │  │ ……（共 6 段）          │
│  └────────────────────┘  │ 做事要认真……          │
│                          │ [读整篇] [返回故事详情]│
└──────────────────────────┴───────────────────────┘
```

- **布局**：`.story` 用 grid；窄屏 `grid-template-columns: 1fr`，宽屏 `5fr 6fr` + `grid-template-areas`（`media` / `body` / `actions` / `hint`）+ `align-content: center`。
- **图片**：容器 `aspect-ratio: 4 / 3`，`img { width: 100%; height: 100%; object-fit: cover }`；窄屏 `width: min(100%, 58vh)` 居中。**不能**用 `width:100% + max-height + contain`——那会把画面缩窄并在两侧露出容器底色（v0.2.2 的窄图问题）。
- **状态**：无页码、无 query；旧链接 `?page=n` 被忽略（组件不读 `page`）。
- **正文**：`card.pages.map((p) => <p>{p.text}</p>)`，段间距 10px，字号 `clamp(17px, 2.4vh, 21px)`、行高 1.75。
- **朗读**：`pages.map((p) => p.text).join('')`，保留 `speakOnEnter`（进页即读整篇）。
- **返回**：优先 `location.state.listUrl`，否则 `/card/{id}`；Esc 同返回。
- **滚动**：容器 `overflow-y: auto`，确保矮屏能读到寓意与按钮。

## 5. 图片管线

| 项 | 值 |
| --- | --- |
| 尺寸 | 480×360（4:3），与分类封面同规格 |
| 质量 | WebP q78 |
| 数量 | **50 张**（每故事 1 张综合图；另有分类封面 1 张） |
| 场景模板 | 18 个：`meadow` `forest` `hill` `house` `kitchen` `garden` `room` `road` `pond` `snow` `river` `night` `farm` `cave` `sea` `castle` `school` `rain` |
| 主体 | `STORY_SUBJECTS` 98 个 key（`pig` / `wolf` / `rabbit` / `frog` / …），小蝌蚪单独矢量绘制 |
| 综合图规则 | 背景取首个分镜的 `scene`；主体先按「角色 vs 道具」分组（`STORY_PROPS` 为环境/用品集），**角色优先**，再比出现次数，同票时角色比首次出场、道具比**最后**一次出场（结局道具更重要）；最多 3 个：主角居中最大（1/2/3 主体对应 font 150/132/126），配角分列左右（font 96 或 88）；水面场景主体整体下移（`pond` +74 / `river` +34 / `sea` +30），天空类主体（云/日月星/雨雪/飞虫）上抬 46 |
| 配色 | 主体暖墨 `#4A4038` + 径向奶油光晕 `#FFF8EC`（夜间/洞穴降到 0.3）；因 librsvg 不支持彩色 emoji，全项目统一单色剪影风 |
| 幂等 | 已存在即跳过，`--force` 全量重绘，`--only=stories` 只画故事；`--prune` 删除已废弃的 `{n}.webp` |
| 解析 | 从 `stories.ts` 按 `{ slug:` 分块，页行正则 `\{ text: '...', scene: '...', subject: '...' \}`，仅用于聚合分镜信息 |

**种子 → 卡片映射**：`slug` → `id = stories-{slug}`；`image = .../cover.webp`（综合图）；`pages[i]` 只存 `text`（无 `image`）。

> **v0.3 变更提示**：本表「主体」「配色」「综合图规则」三行的 emoji 单色剪影方案已被**程序化扁平插画**取代（`STORY_SUBJECTS` 删除，改为 `CAST_SPECS` + `CAST_TONES`，光晕退场，落脚线、主体尺寸与下移量全部改口径）。尺寸 / 质量 / 场景模板 / 幂等开关仍按本表。详见 `NFR/v0.3/技术方案-主体插画.md`（ADR-C1）。

## 11. 验收步骤（手工）

1. 首页 → 「故事」→ 显示「第 1 / 5 页」+ 四个组 chips。
2. 点「生活习惯」→ 15 张、2 页；翻到第 2 页 → URL 为 `?group=story-habit&page=2`。
3. 点「小熊刷牙」→ 详情页有「开始阅读」→ 进入 `/story/stories-brush-teeth`。
4. 页面一次显示全部 6 段正文 + 一张综合插图；无「上一页 / 下一页」、无页码。
5. 点「读整篇」→ 从头到尾读完 6 段；关闭语音则按钮禁用但阅读正常。
6. 点返回 → 回到详情页 → 再返回 → 回到 `?group=story-habit&page=2`；Esc 与返回一致。
7. 手动访问 `/story/stories-three-pigs?page=3` → 仍展示整篇（参数忽略）。
