## 2. 分龄模式的领域设计

### 2.1 龄段与难度映射

```ts
// src/domain/entities/card.ts 追加（与 Difficulty 同处，避免新开文件）
export type AgeBand = '1-3' | '3-6';

export const AGE_BANDS: readonly AgeBand[] = ['1-3', '3-6'];

export const AGE_BAND_LABEL: Record<AgeBand, string> = {
  '1-3': '1–3 岁',
  '3-6': '3–6 岁',
};

/** 入口卡片上的一句说明：两档的「看什么」必须有区别，否则家长分不出意义 */
export const AGE_BAND_TAGLINE: Record<AgeBand, string> = {
  '1-3': '认物 · 认人 · 日常动作',
  '3-6': '认字 · 读诗 · 讲成语',
};

/** 难度 2 为重叠带：同一张卡在两档都出现（1–3 岁并入难度 2 才不会出现空分类） */
export const AGE_BAND_DIFFICULTIES: Record<AgeBand, readonly Difficulty[]> = {
  '1-3': [1, 2],
  '3-6': [2, 3],
};
```

### 2.2 领域纯函数（`domain/services/catalog.ts` 追加）

```ts
export function isAgeBand(value: string | null | undefined): value is AgeBand {
  return value === '1-3' || value === '3-6';
}

export function matchesBand(card: Card, band: AgeBand): boolean {
  return AGE_BAND_DIFFICULTIES[band].includes(card.difficulty);
}

export function countCardsByBand(cards: readonly Card[], band: AgeBand): number {
  return cards.reduce((sum, card) => (matchesBand(card, band) ? sum + 1 : sum), 0);
}
```

> 领域层仍然零浏览器依赖：`AgeBand` 是纯类型 + 纯表，可在 node 环境直接测。

### 2.3 URL 约定（沿用 v0.7「URL 是唯一事实源」）

| 地址 | 含义 |
| --- | --- |
| `#/age/1-3` | 分龄分类墙（新增页面） |
| `#/c/animals?band=1-3` | 分类页只看该龄段 |
| `#/c/animals?band=1-3&group=numbers&page=2` | 龄段 + 主题组 + 页码共存 |
| `#/card/animals-dog?band=1-3` | 详情页按该龄段序列翻页 |

规则：`band` 非法或缺失一律视为「不限龄段」，**不报错、不跳转**（与 v0.7 搜索对 `?q=` 的容错一致）。

## 4. 拼音候选（US-W5）

### 4.1 为什么是「脚本生成字典」而不是运行时引库

`pinyin-pro` 的 `pinyin` API ESM 体积 307 kB（gzip 134 kB）。为了管理区一个输入框把 134 kB 塞进懒加载 chunk 不划算，且违背项目「运行时零新依赖」的偏好。

因此照 `prepare:images` / `prepare:audio` 的老路走：**构建期用 `pinyin-pro`（devDependency）生成精简字典，产物进 `src/`，运行时零依赖**。

### 4.2 字典生成脚本

`scripts/build-pinyin-dict.mjs`（新增，`npm run prepare:pinyin`）：

1. 按 GB2312 一级汉字编码区间解出 3755 字（`0xB0A1`–`0xD7F9`，双字节逐位推进，跳过非法区）；
2. 对每字取全部读音：`pinyin(ch, { multiple: true, type: 'array', toneType: 'symbol' })`；
3. 输出 `src/data/pinyin/dict.ts`：

```ts
/** 由 scripts/build-pinyin-dict.mjs 生成，请勿手改。数据源：pinyin-pro（MIT） */
export const PINYIN_DICT: Readonly<Record<string, readonly string[]>> = {
  '长': ['cháng', 'zhǎng'],
  '大': ['dà', 'dài'],
  // ...
};
```

4. 脚本尾部打印字数与文件体积，并断言「字数 ≥ 3700」；再生成一次结果必须逐字节一致（幂等）。
5. 授权登记：`pinyin-pro` 为 MIT（已核对 GitHub `license.spdx_id`），字典产物在文件头注明来源。

体积预期：3755 字 × 平均 1.3 读音 ≈ 45–55 kB 原始，gzip 20–25 kB。**只被管理区 chunk 引用**，主 chunk 不受影响。

### 4.3 表单交互（`PinyinSuggest` 组件）

新文件 `src/features/admin/ui/PinyinSuggest.tsx`：

```ts
interface Props {
  zh: string;
  /** 拼音框当前值：点选时按位沿用，避免把家长已确认的音改回首读音（v0.8 复审补） */
  value?: string;
  /** 父组件持有拼音框的值，本组件只拼不读以外的逻辑，避免与受控状态双源 */
  onPick: (next: string) => void;
}
```

- 按 `Array.from(zh.trim())` 逐字查 `PINYIN_DICT`，一个字一行：`长` + chips `cháng` `zhǎng`；查不到的字收进 `missing`（去重）；
- 维护本地 `picked: (string | undefined)[]`；点某个 chip 时，按优先级补齐整串：
  - **被点的那一位 = 所点读音**；
  - **本次已选位** `picked[i]`；
  - **拼音框里同位置的已有音节** `value.trim().split(/\s+/)[i]`——家长手输或上次点选的音不被改写（否则「点一个本来就对的字」会把另一个多音字改回首读音，属于给孩子看的内容事故）；
  - 以上都没有才用 `slot.readings[0]` 兜底（一次点击就能得到完整串）；
  - 缺字时槽位与 `value` 的音节对不上位，`value` 一律不沿用（宁可不猜，也不错配）；
  - 拼好立即 `onPick(next.filter(Boolean).join(' '))`；
- **不监听 `zh` 自动写库**（守住 AGENT.md §6 的底线：只有家长的手势能改拼音框）；
- 全部字都不在字典里 → 不渲染候选区，显示 `「龘」不在字典里，请手输拼音`（点名具体字）；部分缺字时在候选区上方提示「「龘」不在字典里，请手动补这几个字的音节」，已知字照样可点选；
- `zh` 变化时已选音作废（`state.zh === zh` 才复用 `picked`）；若上一个词选过音、中文又被改动，额外提示「中文改过了，拼音还是上一个词的，请重新点选或手动确认」——不静默改写拼音框，但不让家长以为它已经跟着改了。

### 4.4 接入点

`CardForm.tsx` 的「拼音（带声调）」字段下方渲染 `<PinyinSuggest zh={zh} value={pinyin} onPick={setPinyin} />`（`value` 必传：点选时靠它保住家长已确认的音节）。导入、种子、批量操作均不接入。

## 7. 决策记录

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| W1 | 分龄**复用 `difficulty`**，不加 `ageBand` 字段 | 数据 v0.1 就标好了；加字段会让 809 张卡与家长自建卡都要补录，且两套「年龄」字段必然打架 |
| W2 | 龄段走 **URL 查询参数**（`?band=`），不做全局设置项 | 与 v0.7「URL 唯一事实源」一致：可分享、可返回、两个 tab 各看各的；全局设置项会让家长忘记自己开过滤 |
| W3 | 拼音候选**构建期生成字典**，运行时零依赖 | 134 kB（gzip）的运行时库只为管理区一个输入框，代价与收益不匹配；脚本生成与图片 / 音频管线同构 |
| W4 | 拼音只做**按字候选**，不做整词猜测 | 多音字组合爆炸且猜错会被家长当真；按字列出全部读音，选择权在人，错误率可控 |
