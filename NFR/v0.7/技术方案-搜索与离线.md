## 2. 全局搜索

### 2.1 复用而非重写

搜索算法直接复用 `searchCards(cards, keyword)`，命中范围：`zh` / `en` / 带声调 `pinyin` / 去声 `pinyin` / `tags`。前台只做三件事：取词、截页、渲染。

```ts
const keyword = searchParams.get('q') ?? '';
const trimmed = keyword.trim();
const hits = useMemo(() => (trimmed ? searchCards(cards, trimmed) : []), [cards, trimmed]);
```

`cards` 来自 `useCatalog()`，已是 `sortCards` 后的全量（809 张）。809 × 5 个字段的 `String.includes` 在 200 kB 量级文本上实测 < 5 ms，所以**不加防抖**：防抖会把「边打边出结果」变成「停手才出结果」，对全内存过滤反而是负优化。

### 2.2 页面结构

```
src/features/search/ui/SearchPage.tsx
  <header class="topbar topbar--bordered topbar--wide">   ← 返回 + 搜索框（autofocus）
  <main class="page page--wide">
    命中提示（「找到 N 张 · 关键词「x」」/ 空态引导）
    <div class="grid-cards">  CardTile × 12（复用分类页组件）
    <nav class="pager">       每页 12 张
    <div class="search-browse"> 命中 ≤ 6 张或 0 张时补分类入口
```

- **URL 是唯一事实来源**：`?q=` 与 `?page=` 只由 `setSearchParams(params, { replace: true })` 改写，输入框的 `value` 直接读 URL。不做「本地 state + URL 双向同步」——两处状态互相追赶时，光标位置会跳。
- 关键词变化时 `page` 归 1；`replace: true` 避免每敲一个字都往历史里塞一条记录。
- 空关键词不渲染网格，给四条示例（`苹果` / `apple` / `pingguo` / `小狗`）作为可点 chip，覆盖中文 / 英文 / 拼音 / 多字词四类输入。
- 结果卡片的分类角标：新增 `.card-tile__cat`，绝对定位在封面**右下角**（左上角会压住图片主体），取 `category.name`。
- 命中 ≤ 6 张时右侧会留大片空白，追加「按主题翻一翻」的 22 个分类 chip；命中 0 张时同样给出口（「换个思路：按主题翻一翻」），不让家长停在一张空页上。

### 2.3 返回链路

`CardTile` 已把 `listUrl = pathname + search` 放进 `state`，详情页 `listUrl` 优先取 state：

```ts
const listUrl = (location.state as { listUrl?: string } | null)?.listUrl ?? ...
```

因此「搜索 → 详情 → 返回」天然回到原 `?q=` 与页码，无需改动详情页。

**取舍**：详情页的翻页序列仍按「同分类 `sortOrder`」构建，不按搜索结果集。原因有三：① 搜索结果跨分类，`buildCardSequence` 的入参是 `categoryId`；② 若要按结果集翻页，详情页需要额外接收一个可能长达 800 条的 id 列表，URL 与 `state` 都会膨胀；③ 「点开一张后往同分类的后一张翻」与分类页行为一致，家长已有预期。该取舍写入 §7 ADR-V2。

### 3.1 manifest

`public/manifest.webmanifest`：

```json
{
  "name": "童识 · 认知卡片",
  "short_name": "童识",
  "description": "1–3 岁启蒙认知卡片：看图片、认汉字、说英语",
  "lang": "zh-CN",
  "dir": "ltr",
  "start_url": "./",

  "display": "standalone",
  "orientation": "portrait-primary",
  "background_color": "#FDFCF8",
  "theme_color": "#2F6B57",
  "icons": [
    { "src": "./icons/icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any" },
    { "src": "./icons/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any" },
    { "src": "./icons/icon-maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }

```

- `start_url` / `scope` 用相对 `./`：与 `vite base: './'` 一致，静态托管在任意子路径都能装。
- 图标由 `scripts/build-icons.mjs` 用 **sharp**（已在 devDependencies）从 `public/icons/icon.svg` 渲染三份 PNG；同一份 SVG 写 `favicon.svg` 供浏览器标签页使用。

### 3.2 Service Worker 策略

手写 `public/sw.js`，不引 Workbox（零新依赖，逻辑 60 行内可审）：

| 请求类型 | 策略 | 说明 |
| --- | --- | --- |
| 导航请求（`mode: navigator`） | 网络优先，失败回退缓存的 `index.html` | 有网永远拿最新外壳；断网仍能打开 |
| 同源静态资源 `.js` / `.css` / `.webp` / `.mp3` / `.svg` / `.png` | 缓存优先，未命中则请求并写缓存 | 内容按 hash 或固定文件名，长期不变 |
| 跨源（GitHub 外链等） | 不拦截 | 避免把第三方请求卷进缓存 |

缓存名固定为 `early-learn:v1`（`public/sw.js` 顶部常量）。**不引构建期版本注入**：`public/` 下的文件不参与打包，注入需要额外的构建脚本；而本项目的更新链已由两件事闭合——① 导航请求永远先走网络，联网即拿到新 `index.html`；② 静态资源文件名带内容 hash，新壳引用新文件名，自然绕过旧缓存。`install` 里 `skipWaiting()`、`activate` 里 `clients.claim()`，装完即接管；`activate` 同时清理同前缀（`early-learn:`）的旧缓存。

预缓存只放外壳：`./`、`./index.html`、`./manifest.webmanifest` 与两张图标，用 `Promise.allSettled` 逐个 `add`——单张失败不能拖垮整个 `install`。图片与音频共 6.7 MB，全部交给运行时缓存。

### 3.3 注册

`src/app/pwa.ts`：

```ts
export function registerServiceWorker(): void {
  if (typeof navigator === 'undefined' || !('serviceWorker' in navigator)) return;
  if (!import.meta.env.PROD) return;            // dev / vitest 不注册，避免干扰 HMR
  const base = import.meta.env.BASE_URL || './';
  window.addEventListener('load', () => {
    void navigator.serviceWorker.register(`${base}sw.js`, { scope: base }).catch(() => {});
  });
}
```

`main.tsx` 在 `createRoot(...).render()` 之后调用一次。`import.meta.env.PROD` 判断让 `vitest`（`NODE_ENV=test`）与 `vite dev` 都不会注册，测试环境无需 mock；注册失败静默降级——离线是增强能力，不能因为宿主不支持 SW 就拿不到正常浏览。

### 3.4 安装入口

不新增「安装」按钮：Chrome / Edge 在满足条件时自动出安装提示；iOS Safari 走「分享 → 添加到主屏幕」。设置页「关于」区补一句说明，避免家长找不到。

## 4. 路由懒加载

```tsx
const CardAdmin = lazy(() => import('../features/admin/ui/CardAdmin').then((m) => ({ default: m.CardAdmin })));
```

| 页面 | 处理 | 理由 |
| --- | --- | --- |
| `CardAdmin` / `CategoryAdmin` / `DataAdmin` | `lazy` | 管理区含表单、导入导出、家长门，普通浏览永远用不到 |
| `QuizPage` | `lazy` | 游戏页，只在点「听音选图」时进 |
| `StoryReaderPage` | `lazy` | 只在点故事卡时进 |
| `GuidePage` | `lazy` | 静态说明页 |
| 首页 / 分类 / 详情 / 收藏 / 最近 / 复习 / 搜索 / 设置 | 静态 | 高频或极小，拆开反而多一次往返 |

`<Suspense>` 放在 `AppShell` 的 `<Outlet />` 外层——只在页面出口内兜住懒加载，切页时页头页脚不会跟着消失：

```tsx
function RouteFallback() {
  return <div className="page page--wide"><p className="section-hint">正在打开…</p></div>;
}
```

占位与页面同宽同内距，切换时容器高度不跳。

## 5. 超宽屏补档与顶栏对齐

```css
@media (min-width: 1700px) {
  :root { --page-max-wide: 1680px; }
}

/* 顶栏内容与所属容器左边缘对齐：容器宽与内距各由一个变量给出 */
.topbar { --topbar-max: var(--page-max); --topbar-pad: 20px; }
.topbar--hero { --topbar-max: var(--page-max-wide); --topbar-pad: 24px; }
.topbar--wide { --topbar-max: var(--page-max-wide); --topbar-pad: 24px; }
.topbar--narrow { --topbar-max: var(--page-max-detail); --topbar-pad: 32px; }
.topbar--story { --topbar-max: 1120px; --topbar-pad: 16px; }

/* 必须排在四类修饰类之后：同为单类特异性，靠顺序覆盖它们的 padding 左右值 */
@media (min-width: 1100px) {
  .topbar {
    padding-inline: max(var(--topbar-pad), calc((100% - var(--topbar-max)) / 2 + var(--topbar-pad)));
  }
}
```

- 用 `%` 而不是 `100vw`：`100vw` 含滚动条宽度，会让宽屏下顶栏比正文向右偏 8 px。
- 内距必须比对（`--topbar-pad`）：只对齐容器宽度不写内距，1440 下会差 4 px、详情页差 8 px。
- 变量覆盖写在 `:root` 里，`.page--wide` 与顶栏同步生效，不需要第二处改动；`.detail` 的 960 也从硬编码改为 `--page-max-detail`。
- 实测（CDP 量 `mainLeft + paddingLeft` 对比 `topbarLeft + paddingLeft`）：1826 / 1440 / 360 / 详情页四档全部相等（90 / 24 / 14 / 272）。
- 顺带修掉一处 v0.6.2 遗留：详情页普通卡把图块改成正方形后，右列 `words` 贴首行底、`actions` 贴次行顶，两截重心上下错开 220 px（图中心 468 / 文字块 691）。改法是普通卡 `grid-template-rows: auto auto` + `align-content: center`，让整组跟着图片居中；诗词 / 成语卡内容会超出容器，居中会让溢出部分滚不到，故用 `:not()` 排除。修后两边中心 468 / 467。

## 7. 决策记录

| ADR | 结论 | 理由 / 放弃的方案 |
| --- | --- | --- |
| V1 | 搜索完全在前端做，复用 `searchCards` | 809 张全量已在内存，过滤 < 5 ms；放弃「生成静态索引 JSON」（多一次请求、多一份与数据不同步的文件） |
| V2 | 详情页翻页序列仍按同分类，不按搜索结果集 | 结果集跨分类且可达 800 条，塞进 URL / `state` 会膨胀；放弃「结果集翻页」（需改 `CardDetailPage` 入参与 `buildCardSequence` 语义） |
| V3 | 手写 `sw.js` 而不是引 Workbox | 零新依赖、60 行可审；策略只有「导航网络优先 + 静态缓存优先」两种，Workbox 的运行时注入与 precache manifest 对 7 MB 资产是过度设计 |
| V4 | 懒加载只拆低频页，不动高频页 | 高频页拆开会让「点一张卡」变成「等一个 chunk」，收益为负；管理区 + 游戏 + 故事 + 说明四块足够吃掉首屏的冗余 |
| V5 | 超宽屏用 `:root` 变量覆盖 + `%` 反算顶栏内距 | 一处变量同时管容器与顶栏，避免第二套硬编码；放弃 `100vw`（滚动条导致 8 px 偏移） |

## 8. 风险与后续

| 风险 | 现状 | 后续 |
| --- | --- | --- |
| SW 缓存旧外壳导致更新不及时 | 导航网络优先 + 静态资源带 hash 文件名 + `install` 里 `skipWaiting`，联网即刷新 | 若真机出现「更新后仍旧版」，改为页面 Toast 提示刷新 |
| 首次安装时预缓存 7 MB 资产耗时 | 只在 `install` 阶段缓存外壳与图标，图片音频走运行时缓存 | 若用户反馈首屏白块，再评估「空闲时段批量预取」 |
| 搜索结果仍按 `sortOrder` 排序 | 同分类内顺序稳定，跨分类按分类顺序 | 若家长反馈「搜 apple 要翻两页」，再引入相关度（完全匹配 > 前缀 > 包含） |
| ≥1700 px 容器 1680 后每卡更宽 | 1440 / 6 列每卡 205 px → 1680 / 6 列每卡 245 px，图片为 webp 足够 | 无需处理 |
